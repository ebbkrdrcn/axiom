# DSL Program for TASK-0100 Rate Limiter

## Program

```text
t1:Task = TASK-0100
a1:ADR = t1.adr

LOOP:work
  DELEGATE implementation
  VERIFY t1
    → FALLBACK
        → TRANSITION "Blocked"
        → STOP
  
  WHEN t1.accepted
    → BREAK
  
  WHEN t1.rejected
    → TRANSITION t1 "Debugging"
    → DELEGATE diagnosis
    → TRANSITION t1 "InProgress"

TRANSITION t1 "Review"
HITL:done[approved, rejected]("Is TASK-0100 done?")
WHEN done.approved
  → TRANSITION t1 "Done"
WHEN done.rejected
  → TRANSITION t1 "InProgress"
```

## Assumptions

1. **ADR Binding:** The ADR linked to TASK-0100 is ADR-0100, which is bound as `a1` at the start of the process and remains available throughout.

2. **Implementation and Diagnosis Actors:** The `DELEGATE implementation` and `DELEGATE diagnosis` statements refer to external actors (developers, CI/CD systems, etc.) who perform the work. The program does not specify how they are invoked or their details.

3. **Verification Outcome:** `VERIFY t1` establishes exactly one outcome (`accepted` or `rejected`), or fails if the criteria are undecidable. The failure case is handled by the `FALLBACK`, which sets the process state to "Blocked" and stops execution.

4. **Loop Termination:** The loop exits only when `t1.accepted` is verified. If verification rejects, the task transitions to Debugging, diagnosis is delegated, the task moves back to InProgress, and the loop repeats.

5. **After Acceptance:** Once the task is verified as accepted, it is transitioned to Review immediately after the loop, and a human is asked to confirm completion.

6. **Human Decision:** The human is asked once, after the task reaches Review. If the human approves, the task moves to Done. If the human rejects, the task moves back to InProgress and the process ends.

7. **Task Definition Compliance:** All transitions respect the Task Definition's transition table and preconditions:
   - `InProgress → Debugging` requires `verified: rejected`
   - `Debugging → InProgress` requires `none`
   - `InProgress → Review` requires `verified: accepted`
   - `Review → Done` requires `human: approved`
   - `Review → InProgress` requires `none`

8. **No Concurrent Changes:** The fixture entities (TASK-0100 and ADR-0100) are not modified by other concurrent processes during this execution.

9. **Process State:** The process state is set to "Blocked" only if verification fails to determine an outcome. Otherwise, the process state remains unset (implicitly "none") until that point.
