# Validity Analysis for Snippets A–D

## Snippet A

```
t1:Task = TASK-0100
LOOP:work
  a1:ADR = t1.adr
  VERIFY t1
  WHEN t1.accepted
    → BREAK
```

**Answer: INVALID**

**Rules broken: V11**

**Explanation:**

Rule V11 states: "a binding is indented, or follows a statement that is not a binding, or binds a name that is already bound, or its relation starts from a name not bound on an earlier line".

The binding `a1:ADR = t1.adr` at line 3 is indented inside the `LOOP:work` body. According to the DSL specification, bindings MUST appear at the top of the program, unindented, before every other statement (rule V11 and section **Binding**). An indented binding is invalid.

## Snippet B

```
a1:ADR = t1.adr
t1:Task = TASK-0100
VERIFY a1
```

**Answer: INVALID**

**Rules broken: V11**

**Explanation:**

Rule V11 states: "a binding is indented, or follows a statement that is not a binding, or binds a name that is already bound, or its relation starts from a name not bound on an earlier line".

The binding `a1:ADR = t1.adr` at line 1 attempts to bind the target of a relation of `t1`, but `t1` is not bound on an earlier line. It is bound on line 2, which comes *after*. The binding `a1` references a name `t1` that has not yet been bound, violating rule V11.

## Snippet C

```
t1:Task = TASK-0100
TRANSITION t1 "Done"
```

**Answer: VALID**

**Explanation:**

This program is syntactically and structurally valid:

- The binding `t1:Task = TASK-0100` is at the top of the program, unindented, before any other statement. ✓
- `TRANSITION t1 "Done"` uses the bound name `t1`. ✓
- No validity rules are broken.

Note: While this program is valid, its execution will fail at runtime. The fixture shows TASK-0100 is in status `InProgress`, and the Task Definition permits no direct transition from `InProgress` to `Done`. However, syntactic validity and runtime success are separate concerns. The program structure conforms to rules V1–V12.

## Snippet D

```
t1:Task = TASK-0100
HITL:t1[approved, rejected]("Done?")
TRANSITION t2 "Done"
```

**Answer: INVALID**

**Rules broken: V12**

**Explanation:**

Rule V12 states: "`TRANSITION <name> "<status>"` uses a name that is not bound, or a bound name is used as a `HITL` name".

This snippet violates V12 in two places:

1. Line 2: `HITL:t1[...]` uses `t1` as a HITL name, but `t1` was bound on line 1. According to the DSL specification, "A bound name MUST NOT also be used as a `HITL` name (V12)".

2. Line 3: `TRANSITION t2 "Done"` uses `t2`, which is not bound anywhere in the program. This violates V12.
