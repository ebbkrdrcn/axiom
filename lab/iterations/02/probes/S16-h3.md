# Execution Trace for TDD Loop

## Program
```
LOOP:tdd
  DELEGATE implementation
  DELEGATE tests
  VERIFY tests
  WHEN tests.accepted
    → TRANSITION "Review"
    → BREAK
  WHEN tests.rejected
    → TRANSITION "Debugging"
    → DELEGATE diagnosis
EMIT source-code
```

## Events
- Iteration 1: `VERIFY tests` establishes `rejected`
- Iteration 2: `VERIFY tests` establishes `accepted`

## Execution Trace

```trace
1. DELEGATE implementation -> done
2. DELEGATE tests -> done
3. VERIFY tests -> outcome tests.rejected
4. WHEN tests.accepted -> false: skip
5. WHEN tests.rejected -> true: run flow
6. TRANSITION "Debugging" -> state = "Debugging"
7. DELEGATE diagnosis -> done
8. LOOP:tdd -> loop again
9. DELEGATE implementation -> done
10. DELEGATE tests -> done
11. VERIFY tests -> outcome tests.accepted
12. WHEN tests.accepted -> true: run flow
13. TRANSITION "Review" -> state = "Review"
14. BREAK -> break
15. EMIT source-code -> done
16. (end of program) -> end
```

## Final State
**State: `"Review"`**

## Explanation

**Iteration 1:**
- The loop body executes: implementation is delegated, tests are delegated, and then verified as rejected.
- The first `WHEN tests.accepted` is false, so it is skipped.
- The second `WHEN tests.rejected` is true, so its flow runs: the process transitions to "Debugging" state and diagnosis is delegated.
- The loop body ends, so execution returns to the start of the loop (step 8: loop again).

**Iteration 2:**
- The loop body executes again: implementation is delegated, tests are delegated, and then verified as accepted.
- The first `WHEN tests.accepted` is now true, so its flow runs: the process transitions to "Review" state and `BREAK` is executed.
- `BREAK` exits the loop immediately, so no more loop iterations occur.
- Execution continues after the loop with `EMIT source-code`.
- The program ends.

The final state of the process is **`"Review"`**, which was set by the most recent (and only) `TRANSITION` statement that executed after the second loop iteration.
