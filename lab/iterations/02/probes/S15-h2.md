# DSL Execution Trace Analysis

## Program
```
FORK
  → DELEGATE lint
      VERIFY lint
      WHEN lint.rejected
        → STOP
  → DELEGATE docs
      EMIT docs
JOIN
EMIT build
```

## Given Events
- `VERIFY lint` establishes `rejected`
- At that moment, the docs branch has executed `DELEGATE docs` but not `EMIT docs`

## Step-by-Step Execution Trace

```trace
1. FORK -> branches started
2. DELEGATE lint -> done
3. DELEGATE docs -> done
4. VERIFY lint -> outcome lint.rejected
5. WHEN lint.rejected -> true: run flow
6. STOP -> stop
```

## Analysis

### Is `EMIT docs` executed?
**NO**

The `STOP` statement (step 6) terminates the entire execution immediately. According to the specification: "Ends the entire execution immediately. No further statement runs anywhere, including other `FORK` branches."

At the moment `STOP` is executed, the docs branch has completed `DELEGATE docs` but has not yet reached `EMIT docs`. Since `STOP` halts all execution, `EMIT docs` never runs.

### Is `JOIN` completed?
**NO**

The `JOIN` appears after the `FORK`. According to the specification: "A pending `JOIN` never completes" when `STOP` is executed. The execution terminates at step 6 before reaching the `JOIN` statement.

### Is `EMIT build` executed?
**NO**

`EMIT build` appears after the `JOIN`. Since execution stops at step 6 (the `STOP` statement), the `EMIT build` statement is never reached.

## Summary
When the lint branch's `WHEN lint.rejected` condition evaluates to true and executes `STOP`, the entire process terminates immediately. This prevents:
- The docs branch from executing `EMIT docs`
- The `JOIN` from completing
- The final `EMIT build` from executing

Only the lint branch completes, executing through the `STOP` statement.
