# Analysis of DSL Program Execution

## Question 1: Can `DELEGATE implementation` start before the design has been delivered?

**Answer: No.**

**Justification:**

According to "Execution in ten rules" (Rule 1):
> Statements run one at a time, in the order written. Each statement finishes before the next starts. Only `FORK` runs things concurrently.

The program has:
```
DELEGATE design
DELEGATE implementation
```

Since `DELEGATE implementation` is listed after `DELEGATE design`, and Rule 1 requires statements to be executed sequentially (finishing before the next starts), `DELEGATE implementation` cannot start until `DELEGATE design` delivers its result.

---

## Question 2: When is `EMIT release` executed relative to the docs and changelog branches?

**Answer: `EMIT release` executes immediately after the `FORK` starts the concurrent branches, while the branches are still running.**

**Justification:**

The specification for `FORK` (under Control → FORK) states:
> No `JOIN` follows → Execution continues immediately after the `FORK` while the branches run.

The program contains:
```
FORK
  → DELEGATE docs
  → DELEGATE changelog
EMIT release
```

There is no `JOIN` statement after the `FORK`. Therefore, execution continues immediately after the fork statement. Since `DELEGATE docs` takes 1 hour and `DELEGATE changelog` takes 5 minutes, `EMIT release` executes long before either branch completes.

---

## Question 3: Is it guaranteed that docs exist when `EMIT release` executes?

**Answer: No. It is not guaranteed.**

**Justification:**

As established in Question 2, `EMIT release` executes immediately after the `FORK` starts the branches. The specification does not require `FORK` branches to complete before continuing.

Since:
- The `docs` branch is expected to take 1 hour
- `EMIT release` executes immediately after the fork begins (before 1 hour has elapsed)
- The execution does not wait for branches to finish (no `JOIN` is present)

It is **not guaranteed** that `docs` will have been delivered before `EMIT release` executes.

To guarantee that docs exist when `EMIT release` executes, a `JOIN` statement would need to be inserted between the `FORK` and `EMIT release`:

```
FORK
  → DELEGATE docs
  → DELEGATE changelog
JOIN
EMIT release
```

With this modification, `EMIT release` would only execute after all branches (including `docs`) are complete.
