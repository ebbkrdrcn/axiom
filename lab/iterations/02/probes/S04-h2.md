# go_harness DSL Program

```
REQUIRE deployment-target
HITL:region[eu, us]("Which region to deploy to: eu or us?")
  → FALLBACK
      → TRANSITION "Blocked"
      → STOP
WHEN region.eu
  → DELEGATE eu-deployment
WHEN region.us
  → DELEGATE us-deployment
EMIT deployment-log
```

## Assumptions Made

1. **HITL question wording**: The specification does not prescribe the exact wording of the human-facing question. I assumed a direct, clear phrasing: "Which region to deploy to: eu or us?" Any wording that communicates the choices would be valid.

2. **Answer classification**: I assumed that a human response containing or clearly indicating "eu" or "us" would be classified as usable, and any other response (no answer, ambiguous, off-topic) would be insufficient or unavailable, triggering the FALLBACK.

3. **Identifier names**: The requirement uses informal names like "deployment-target", "eu-deployment", and "us-deployment". I assumed these are valid identifiers (letters, digits, `-` and `_`). The specification's syntax allows these.

4. **State name**: The requirement specifies transitioning to state "Blocked". I assumed this is the exact state name intended; the specification does not constrain state names.

5. **REQUIRE completion**: The specification states that if the item is available, execution continues. I assumed "deployment-target" becomes available from the runtime before the REQUIRE statement completes, without prescribing how (filesystem access, configuration, etc.).

6. **Consecutive WHEN independence**: The two WHEN statements for `region.eu` and `region.us` are consecutive and independent (per rule 3 in **Execution in ten rules**). Both conditions are mutually exclusive since the HITL produces exactly one outcome, so at most one will be true—but the DSL requires both to be written independently.

7. **No alternative paths needed**: The requirement does not mention what happens after either delegation completes (success/failure verification). I assumed the delegated work completes and execution proceeds directly to `EMIT deployment-log` without additional verification steps.
