# Execution Trace and Analysis

## Program
```
TRANSITION "Testing"
WHEN tests.accepted
  → TRANSITION "Review"
DELEGATE tests
VERIFY tests
EMIT test-report
```

**Event:** `VERIFY tests` establishes `accepted`.

## Execution Trace

| Step | Statement | Effect |
|---|---|---|
| 1 | `TRANSITION "Testing"` | `state = "Testing"` |
| 2 | `WHEN tests.accepted` | `false: skip` |
| 3 | `DELEGATE tests` | `done` |
| 4 | `VERIFY tests` | `outcome tests.accepted` |
| 5 | `EMIT test-report` | `done` |
| — | (end of program) | `end` |

## Analysis

**Is `TRANSITION "Review"` ever executed?**

**No.** The statement `TRANSITION "Review"` is never executed.

### Why

A `WHEN` is checked **once** at the moment execution reaches it, not retroactively. At step 2, when the `WHEN tests.accepted` condition is evaluated:

- No `VERIFY tests` has run yet, so no outcome has been established for `tests`
- According to the specification (Execution rule 7): "Before anything establishes it, every `WHEN` on it is false"
- The condition is false, so the flow is skipped

At step 4, `VERIFY tests` establishes the outcome `tests.accepted`, but this occurs **after** the `WHEN` has already been checked and skipped. Per the specification:

> "The outcome is established later → Nothing happens. A `WHEN` is not a standing trigger and is never re-checked."

The DSL is designed this way so that execution proceeds sequentially and deterministically. `WHEN` statements are not event listeners; they are one-time conditional checks.

## Final State

```
"Testing"
```

The process state is set to "Testing" at step 1 and never changes again, since `TRANSITION "Review"` is never executed.
