# Analysis of go_harness DSL Program

## Question 1: Which decision may the agent make by itself, and under what condition?

The agent may make the **wording decision** by itself.

The wording decision is marked with `AUTO`:
```
AUTO HITL:wording[short, detailed]("Short or detailed release notes?")
```

The release decision has no `AUTO`:
```
HITL:release[approved, rejected]("Approve the release?")
```

According to the specification (section **AUTO**), `AUTO` is written directly before a `HITL` decision and means: "resolve the decision automatically when it is sufficiently determined; otherwise ask the human."

**Condition:** The agent may decide the wording by itself when:
- The decision is sufficiently determined (certain) based on available information and applicable criteria
- The decision is within the agent's authority
- More specifically, the agent can determine one single answer from [short, detailed] with certainty

If either condition fails (uncertainty or lack of authority), the human is asked instead.

---

## Question 2: May the agent answer "Approve the release?" itself?

**No.** The agent MUST NOT answer "Approve the release?" by itself, even if all automated checks are green and the agent is highly confident.

**Reason:** The release decision has no `AUTO` marker:
```
HITL:release[approved, rejected]("Approve the release?")
```

From the specification (section **HITL**): "A `HITL` establishes a human decision boundary. It MUST NOT be replaced by an agent decision, unless it is marked with `AUTO`."

Only `HITL` statements marked with `AUTO` may be answered by the agent. This one is not marked `AUTO`.

**Additional constraint:** The specification explicitly states: "A confidence score alone, however high, does not establish certainty." Therefore, even if the agent is "highly confident," that does not establish the certainty required for automatic decision-making.

---

## Question 3: If the wording decision is not clearly determined, what happens?

If the wording decision is not clearly determined, **the human is asked**.

The `AUTO HITL:wording[short, detailed]("Short or detailed release notes?")` is designed to allow automatic resolution only when certain. If the decision is uncertain, the specification (section **AUTO**) states:

> "Anything else | The human is asked, exactly as for a `HITL` without `AUTO`. `FALLBACK` applies to the human's response as usual."

So execution waits at the `HITL`, and the human provides the answer. Once the human responds with "short" or "detailed," the corresponding flow runs (`→ DELEGATE short-notes` or `→ DELEGATE detailed-notes`).

---

## Question 4: If the human answers the release question with "rejected", what happens?

Execution continues with the following flow:

1. `HITL:release[approved, rejected]("Approve the release?")` → the human answer establishes `release.rejected`
2. `WHEN release.approved` → this condition is false (the outcome is `rejected`, not `approved`), so the flow is skipped
3. Execution continues after the `WHEN` statement
4. There are no more statements in the program
5. The program ends normally

**In summary:** The `EMIT release` statement is never reached. The release is not emitted. Execution completes without error.

Note: The specification (section **Execution in ten rules**, rule 2) states: "A `WHEN` is checked once, when execution reaches it. True → run its flow, then continue after the `WHEN`. False → skip it."
