# Validity of the four snippets

## Snippet 1

```
AUTO HITL:deploy[yes, no]("Deploy to production?")
WHEN deploy.yes
  → EMIT deployment
```

**VALID.**

- `AUTO` is written directly before `HITL:deploy[...]`, on the same line, and that `HITL` is a decision form with a name (`deploy`) and a non-empty, non-repeating answer list (`yes`, `no`) — this satisfies V5 ("`AUTO` is not immediately followed, on the same line, by a decision `HITL:<name>[…]`" does not apply here).
- `WHEN deploy.yes` tests the subject/outcome pair `deploy.yes`. The program contains `HITL:deploy[yes, no]` listing `yes` as one of the answers, so the outcome is declared — V6 is satisfied.
- `deploy` is used by only one `HITL` and by no `VERIFY`, and its answer list (`yes`, `no`) is non-empty with no repeated answer, so V7 is satisfied.
- The `→ EMIT deployment` item is a child of `WHEN`, which is a permitted parent for `→` items (V4 is satisfied).
- No `BREAK`, `JOIN`, or `FORK` appears, so V2, V3, V9, V10 are not implicated. Indentation follows the convention (child aligned appropriately, only one level of nesting under `WHEN`), so V1 is satisfied. There is no `FALLBACK`, so V8 does not apply.

No rule is broken.

## Snippet 2

```
AUTO DELEGATE implementation
VERIFY implementation
```

**INVALID — Rule V5.**

Per the specification: "`AUTO` is written directly before `HITL`, on the same line. It applies only to that one `HITL`, which MUST be a decision (with a name and an answer list)." V5 states the program is INVALID if "`AUTO` is not immediately followed, on the same line, by a decision `HITL:<name>[…]`."

Here `AUTO` is immediately followed by `DELEGATE implementation`, not by a decision `HITL`. The specification gives this exact construct verbatim as an explicit invalid example:

```invalid
AUTO DELEGATE implementation
```

So this snippet is INVALID under V5.

## Snippet 3

```
HITL:deploy[yes, no]("Deploy to production?") AUTO
WHEN deploy.yes
  → EMIT deployment
```

**INVALID — Rule V5** (also inconsistent with the grammar/syntax for `hitl` and with the stated placement rule for `AUTO`).

The specification is explicit that "`AUTO` is written directly before `HITL`, on the same line" (section **AUTO**), and the grammar confirms the order: `hitl = ( [ "AUTO" ] , "HITL:" , identifier , "[" ... )` — `AUTO`, if present, must precede `HITL:`. In this snippet, `AUTO` appears *after* the closing `("Deploy to production?")` of the `HITL` statement, i.e. `AUTO` does not immediately precede `HITL:<name>[…]` on the same line at all. This fails V5's requirement that "`AUTO` is [immediately followed], on the same line, by a decision `HITL:<name>[…]`" — there is no such `AUTO`-before-`HITL` pairing present, so the line as written does not form a valid `AUTO HITL` construct, and it does not match any other line form in **Syntax → Lines and statements** either.

Hence the snippet is INVALID (V5).

## Snippet 4

```
AUTO
HITL:deploy[yes, no]("Deploy to production?")
```

**INVALID — Rule V5.**

`AUTO` must be "written directly before `HITL`, on the same line" and "is not a statement on its own." Here `AUTO` occupies its own line, separate from the `HITL:deploy[...]` line that follows it, so it is not immediately followed, on the same line, by a decision `HITL:<name>[…]` — this is exactly what V5 forbids: "`AUTO` is not immediately followed, on the same line, by a decision `HITL:<name>[…]`."

This mirrors the specification's own explicit invalid example of `AUTO` placed alone on a line followed by other content on subsequent lines:

```invalid
AUTO
  WHEN decision.uncertain
    → HITL("Approve?")
```

So Snippet 4 is INVALID under V5.

## Assumptions

The specification does not explicitly restate, outside of the **AUTO** section and the grammar, what happens when `AUTO` appears with tokens in an order other than "`AUTO` immediately before `HITL:<name>[…]` on the same line" (e.g., `HITL ... AUTO`, or `AUTO` on its own preceding line). I assumed that any placement other than the one explicitly permitted ("`AUTO` is written directly before `HITL`, on the same line") falls under the V5 violation "`AUTO` is not immediately followed, on the same line, by a decision `HITL:<name>[…]`," since the specification defines only that one valid placement and gives no alternative reading for these token orders. This is the most direct application of V5's wording and is consistent with the grammar production `[ "AUTO" ] , "HITL:" , ...`, which fixes `AUTO` (when present) as coming immediately before `HITL:`.
