# DSL Task Answers

## Analysis of the Program

The program:
```
DELEGATE design
DELEGATE implementation
FORK
  → DELEGATE docs
  → DELEGATE changelog
EMIT release
```

## Question 1: Can `DELEGATE implementation` start before the design has been delivered?

**Answer: No**

**Justification:**
According to the specification, "Execution in ten rules", Rule 1 states: "Statements run one at a time, in the order written. Each statement finishes before the next starts. Only `FORK` runs things concurrently."

The program has `DELEGATE design` followed by `DELEGATE implementation`. Since these are sequential statements not inside a `FORK`, execution must:
1. Wait for the design actor to deliver the result
2. Only then start `DELEGATE implementation`

The design delivery is a prerequisite; `implementation` cannot proceed until `design` completes, regardless of how long the design takes.

## Question 2: When is `EMIT release` executed relative to the docs and changelog branches?

**Answer: `EMIT release` is executed immediately after the `FORK` starts, before either the docs or changelog branches complete.**

**Justification:**
The specification states: "No `JOIN` → continue immediately". This program has a `FORK` with no corresponding `JOIN` statement.

Per the `FORK` section: "Execution continues immediately after the `FORK` while the branches run."

Therefore:
- When the `FORK` is reached, both branches (`docs` and `changelog`) start concurrently
- Execution does not wait for the branches to finish
- The next statement `EMIT release` executes immediately, even though:
  - `docs` takes 1 hour to complete
  - `changelog` takes 5 minutes to complete
  - Both branches are still running

## Question 3: Is it guaranteed that docs exist when `EMIT release` executes?

**Answer: No**

**Justification:**
Since `EMIT release` executes immediately after the `FORK` starts (as explained in Question 2), and the `docs` branch takes 1 hour to complete, the docs result is not yet available when `EMIT release` runs.

The specification states: "A branch's last statement is done / That branch is complete." The docs branch is not complete at the time `EMIT release` executes.

Additionally, from "Executing a program", Rule 5: "If an event, response, or result is not yet available, the execution waits there." However, `EMIT release` does not wait—it is a sequential statement after the `FORK`, and with no `JOIN` to synchronize, it proceeds immediately.

The `EMIT release` statement produces output based on its own logic, but the docs result from the concurrent branch is not guaranteed to be available at that moment.

## Summary

1. **Sequential constraint**: `implementation` must wait for `design`
2. **No synchronization**: Without a `JOIN`, `EMIT release` runs immediately after `FORK` starts
3. **Race condition**: The docs branch (1 hour) is not complete when `EMIT release` executes (5 minutes + negligible execution time for EMIT)
