# Execution Trace

## Program
```
TRANSITION "Testing"
WHEN tests.accepted
  → TRANSITION "Review"
DELEGATE tests
VERIFY tests
EMIT test-report
```

## Events
- `VERIFY tests` establishes `accepted`

## Validation
The program is valid (all rules V1–V10 satisfied).

## Step-by-step Execution

1. `TRANSITION "Testing"` → `state = "Testing"`
2. `WHEN tests.accepted` → `false: skip`
3. `DELEGATE tests` → `done`
4. `VERIFY tests` → `outcome tests.accepted`
5. `EMIT test-report` → `done`
6. (end of program) → `end`

## Final State
`"Testing"`

## Is `TRANSITION "Review"` ever executed?
**No.**

The `WHEN tests.accepted` condition is checked once, when execution reaches it (line 2). At that point, no outcome for `tests` has been established yet. According to the specification (Outcomes section, rule 7): "Before anything establishes it, every `WHEN` on it is false." Therefore, the condition evaluates to false and the flow under the `WHEN` (which includes `TRANSITION "Review"`) is skipped. The `WHEN` is never re-checked later, even after `VERIFY tests` establishes the `tests.accepted` outcome. Execution continues sequentially through lines 3–5 without running the transition.
