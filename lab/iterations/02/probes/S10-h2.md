# go_harness DSL Analysis

## Task: Analyze the WHEN flow

Given the program:
```
VERIFY review
WHEN review.rejected
  → DELEGATE correction
      VERIFY correction
  → TRANSITION "Rework"
EMIT review-report
```

With `VERIFY review` establishing `review.rejected`:

### 1. Which statements belong to the WHEN flow?

The statements that belong to the `WHEN review.rejected` flow are:
- `DELEGATE correction` (first `→` item)
- `VERIFY correction` (nested under the first `→` item, continuing its flow)
- `TRANSITION "Rework"` (second `→` item)

These are all the statements indented as children of the `WHEN` line.

### 2. Sequential or concurrent, and in what order?

**Sequential.** According to Execution Rule 4: "The `→` items under a `WHEN` or a `FALLBACK` form **one sequential flow**."

The order is:
1. First: `DELEGATE correction`
2. Then: `VERIFY correction` (continues the flow of the first `→` item)
3. Finally: `TRANSITION "Rework"`

### 3. Is `VERIFY correction` part of the WHEN flow?

**Yes.** According to the Indentation and scope section: "A line belongs to the nearest preceding line that is indented **less** than it."

`VERIFY correction` is indented under `DELEGATE correction`, so it belongs to and continues that item's flow within the WHEN flow.

### 4. Is `EMIT review-report` part of the WHEN flow? Is it executed?

**Not part of the WHEN flow.** `EMIT review-report` is at the same indentation level as `WHEN review.rejected`, so it is outside and after the WHEN scope, not nested within it.

**Yes, it is executed.** According to Execution Rule 2: "A `WHEN` is checked once, when execution reaches it. True → run its flow, then continue after the `WHEN`."

Since the condition `review.rejected` is true, the WHEN flow executes, and then execution continues with the next statement, which is `EMIT review-report`.

### 5. If `VERIFY review` had established `review.accepted`, which statements would execute?

Only these statements would execute:
- `VERIFY review` (establishes `review.accepted`)
- `EMIT review-report`

Explanation: The condition `WHEN review.rejected` would be false, so the entire WHEN flow would be skipped (Execution Rule 2: "False → skip it"). Then execution would continue to `EMIT review-report`.
