## 2. Step-by-Step Execution and Final State

**Given events:**
- Repository context is available (implied)
- `VERIFY dependency-upgrade` establishes `accepted`
- The changelog announces a breaking API change
- Two maintainers disagree about whether breaking changes may be merged
- Human answer: "Declined"

**Execution trace:**

```
1. DELEGATE dependency-upgrade -> done
2. VERIFY dependency-upgrade -> outcome dependency-upgrade.accepted
3. AUTO HITL:merge[approved, declined]("Merge the dependency upgrade?") -> waiting
```

At step 3, the agent evaluates whether the decision is certain:
- The merge criterion is "merge when verification accepts" → `dependency-upgrade.accepted` is true
- However, a breaking API change exists that the criterion does not address
- Two maintainers disagree about breaking changes
- This creates **uncertainty**: required information (maintainer consensus on breaking changes) is missing/contradictory, and the applicable criteria (the stated criterion) do not cover the case

Per the `AUTO` specification (Semantic Principles), the agent **cannot determine one single answer reliably**. Uncertainty exists. Therefore, the human is asked.

```
3. AUTO HITL:merge[approved, declined]("Merge the dependency upgrade?") -> outcome merge.declined
4. WHEN merge.approved -> false: skip
5. WHEN merge.declined -> true: run flow
6. TRANSITION "Deferred" -> state = "Deferred"
7. (end of program) -> end
```

**Final state: `Deferred`**

---

## Justification for AUTO Behavior

The `AUTO` clause permits automatic resolution **only** when:
1. The decision is sufficiently determined from available information and criteria, **AND**
2. The decision is within the agent's authority

In this case:
- **Criteria conflict**: The stated criterion ("merge when verified as accepted") is satisfied, but the breaking API change creates a missing criterion boundary
- **Information gaps**: Maintainer disagreement means no consensus guidance exists
- **Uncertainty**: More than one answer is reasonably compatible with available evidence (merge due to passing verification vs. defer due to breaking change + disagreement)

Per the specification: *"A confidence score alone, however high, does not establish certainty."* The agent cannot reliably determine approval, so it asks the human. The human responds "Declined," establishing `merge.declined`, and execution continues to `WHEN merge.declined → TRANSITION "Deferred"`.
