# Validity Analysis: DSL Program

## Status: INVALID

The program violates three validity rules:

### Violations

| Rule | Line | Description |
|------|------|-------------|
| V3 | 7 | `BREAK` is inside a `FORK` branch (first branch starting line 5), and the `LOOP` it would leave (`LOOP:cycle` at line 2) is outside that branch. This violates the rule that `BREAK` inside a `FORK` branch may only leave a `LOOP` also inside that branch. |
| V6 | 11 | `WHEN review.passed` tests an outcome that the program cannot produce. The program contains `VERIFY review` (line 9) which establishes only `review.accepted` or `review.rejected`, never `review.passed`. The specification states: "There are no other VERIFY outcomes: `passed`, `failed`, `ok` and similar are INVALID in a `WHEN`." |
| V8 | 15 | The fallback flow (lines 14-15) ends with `→ TRANSITION "Waiting"`, but the specification requires that "the last item of a fallback flow is not `STOP` or `BREAK`" (rule V8). This fallback must end with `STOP` or `BREAK`, not `TRANSITION`. |

## Conclusion

The program MUST NOT be executed. It is not well-formed.
