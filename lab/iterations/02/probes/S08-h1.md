# Execution of go_harness DSL with Unavailable Requirement

## Analysis

Given program:
```
REQUIRE staging-credentials
DELEGATE deployment
EMIT deployment-log
```

Runtime condition: The staging-credentials cannot be obtained.

## Answers

### 1. What happens at `REQUIRE staging-credentials`?

At `REQUIRE staging-credentials`, the runtime determines that the item (staging-credentials) cannot be obtained. According to the specification (section "REQUIRE", rule for unavailable items with no FALLBACK):

> The runtime determines the item cannot be obtained, and there is no `FALLBACK` | Execution ends, as with `STOP`.

Since this `REQUIRE` statement has no attached `→ FALLBACK` block, execution terminates immediately.

### 2. Is `DELEGATE deployment` executed?

**No.** `DELEGATE deployment` is NOT executed. 

The execution ends at the `REQUIRE staging-credentials` statement before reaching `DELEGATE deployment`. According to the execution rules: "Statements run one at a time, in the order written. Each statement finishes before the next starts" (Execution rule 1). Since the `REQUIRE` causes execution to stop, no subsequent statements are reached.

### 3. Is `EMIT deployment-log` executed?

**No.** `EMIT deployment-log` is NOT executed.

For the same reason as question 2: execution has already terminated at the `REQUIRE` statement, so this final statement is never reached.

### 4. What exactly should the executing agent do?

The executing agent should:

1. **Validate the program** using rules V1–V10. This program is valid (all indentation, REQUIRE structure, and references are correct).

2. **Execute the first statement:** Execute `REQUIRE staging-credentials`.

3. **Determine availability:** Check with the runtime whether `staging-credentials` is available.

4. **Handle unavailability:** The runtime indicates the item cannot be obtained.

5. **Check for a FALLBACK:** Look for an attached `→ FALLBACK` block under this `REQUIRE`. There is none.

6. **End execution:** Immediately end execution as with `STOP` (per the specification). No outcome is established. No remaining statements are executed.

7. **Report the result:** Execution ends normally at the `REQUIRE` statement with the item unavailable and no fallback available. No work is delegated, no logs are emitted.

**Key principle from the specification:** "The agent MUST NOT assume, fabricate, or substitute the item. It MUST NOT skip the `REQUIRE` or continue in a degraded mode."
