## Violations

### V3 — line 7 (`→ BREAK`)

Rule V3: "`BREAK` is inside a `FORK` branch, and the `LOOP` it would leave is outside that branch."

Line 7's `BREAK` sits inside the first branch of the `FORK` at line 4 (branch opened at line 5, `→ VERIFY implementation`). The innermost `LOOP` it would leave is `LOOP:cycle` (line 2), which encloses the `FORK` itself — the loop is *outside* the branch, not nested inside it. Per the `BREAK` section and the `FORK` table: "`BREAK` in a branch: INVALID (rule V3). To leave a loop based on a branch's result, `JOIN` first, then use `WHEN … → BREAK`." That is exactly the pattern this program should have used but did not (it does have a `WHEN … → BREAK` after the `JOIN`, at lines 16–17, but the errant one at line 7 is still present and still invalid).

### V6 — line 11 (`WHEN review.passed`)

Rule V6: "a `WHEN` tests `x.y`, and the program contains neither `VERIFY x` with `y` being `accepted` or `rejected`, nor `HITL:x[…]` listing `y`."

The program does contain `VERIFY review` (line 9), which can only establish `review.accepted` or `review.rejected` (per the **VERIFY** section: "There are no other VERIFY outcomes: `passed`, `failed`, `ok` and similar are INVALID in a `WHEN`"). There is no `HITL:review[…]` anywhere. So `review.passed` is not a producible outcome, and the `WHEN` at line 11 is INVALID under V6.

### V8 — line 15 (`→ TRANSITION "Waiting"`)

Rule V8: "the last item of a fallback flow is not `STOP` or `BREAK`."

The `FALLBACK` attached to `HITL:ship[yes, no]` (line 13, fallback opened at line 14) has exactly one item, line 15, `TRANSITION "Waiting"`, and that is also its last item. Per the **FALLBACK** section: "Its last item MUST be `STOP` or `BREAK` (rule V8). The fallback never continues into the normal flow." Since the flow ends in a `TRANSITION` with no following `STOP`/`BREAK`, this is a V8 violation.
