# Modified go_harness program

**Changes made, and why (per spec only):**

1. **Deploy decision may be agent-made when clearly determined:** prefixed the `deploy` `HITL` with `AUTO` (`AUTO HITL:deploy[...]`). Per the **AUTO** section and the "Who decides a `HITL`" table, `AUTO` means the agent resolves the decision itself only when it is certain and within its authority; otherwise the human is asked exactly as without `AUTO`. This satisfies "may make the decision itself when it is clearly determined" without removing the human path for uncertain cases.
2. **Announce decision stays human-only:** the `announce` `HITL` is left without `AUTO`, per the same table ("no `AUTO`" → "the human; the agent MUST NOT answer").
3. **No usable answer to the announce question → state "Quiet" and stop:** added a `→ FALLBACK` block directly under `HITL:announce`, per the **FALLBACK** section and the `HITL` "What happens" table ("Insufficient or unavailable ... → Run the fallback flow"). The fallback flow is `TRANSITION "Quiet"` followed by `STOP`, satisfying rule V8 (a fallback flow's last item MUST be `STOP` or `BREAK`).

No other statement, ordering, or structure was changed.

**Assumptions:** None beyond the specification were needed — `AUTO` and `→ FALLBACK` are both directly attachable to a `HITL` per the grammar (`hitl = ([ "AUTO" ], "HITL:" ... | "HITL"), "(", string, ")", NL, [fallback]`), so both required changes are expressible without altering any other part of the program.

```text
DELEGATE deployment-plan
AUTO HITL:deploy[approved, rejected]("Deploy the plan?")
WHEN deploy.approved
  → DELEGATE deployment
WHEN deploy.rejected
  → TRANSITION "Replanning"
HITL:announce[yes, no]("Announce the release publicly?")
  → FALLBACK
      → TRANSITION "Quiet"
      → STOP
WHEN announce.yes
  → EMIT announcement
```
