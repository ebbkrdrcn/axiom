# Execution Trace

## Step-by-step execution

```trace
1. FORK -> branches started
2. DELEGATE unit-tests -> done
3. VERIFY unit-tests -> outcome unit-tests.accepted
4. DELEGATE integration-tests -> done
5. JOIN -> waiting
6. VERIFY integration-tests -> outcome integration-tests.rejected
7. JOIN -> joined
8. WHEN unit-tests.accepted -> true: run flow
9. TRANSITION "Ready" -> state = "Ready"
10. WHEN integration-tests.rejected -> true: run flow
11. TRANSITION "Debugging" -> state = "Debugging"
12. (end of program) -> end
```

## Explanation

- **Step 1**: FORK starts both branches concurrently
- **Steps 2-3**: Branch 1 executes completely (unit-tests delegates and verifies as accepted)
- **Steps 4**: Branch 2 executes its first statement (integration-tests delegates)
- **Step 5**: Execution reaches JOIN, but Branch 2 is incomplete (VERIFY integration-tests has not yet finished), so JOIN waits
- **Step 6**: Branch 2's VERIFY integration-tests completes, establishing outcome `integration-tests.rejected`
- **Step 7**: All branches are now complete, so JOIN completes
- **Steps 8-9**: First WHEN condition is true (unit-tests.accepted), so TRANSITION "Ready" executes, setting state to "Ready"
- **Steps 10-11**: Second WHEN condition is true (integration-tests.rejected), so TRANSITION "Debugging" executes, setting state to "Debugging"
- **Step 12**: Program ends normally

## Final State

**State: "Debugging"**

(The most recent `TRANSITION` statement wins, so the final state is "Debugging" since it was executed after "Ready".)
