# DSL Solution

## Program

```text
REQUIRE deployment-target
HITL:region[eu, us]("Which region to deploy to: eu or us?")
  → FALLBACK
      → TRANSITION "Blocked"
      → STOP
WHEN region.eu
  → DELEGATE eu-deployment
WHEN region.us
  → DELEGATE us-deployment
EMIT deployment-log
```

## Assumptions

1. **REQUIRE item name**: I assumed the required item is named `deployment-target` as a single identifier.

2. **HITL name**: I assumed the decision name is `region` to represent the region choice.

3. **Answer list**: I assumed the two possible answers are exactly `eu` and `us`, matching the requirement's wording.

4. **Region question text**: I assumed a natural phrasing of the question based on the requirement.

5. **Delegation names**: I assumed the delegated work items are named `eu-deployment` and `us-deployment` respectively.

6. **Emission artifact name**: I assumed the final output artifact is named `deployment-log`.

7. **FALLBACK placement**: The FALLBACK attaches directly to the HITL (per syntax rule V4) and handles the case where no usable answer is obtained.

8. **Consecutive WHEN statements**: Both `WHEN region.eu` and `WHEN region.us` are independent consecutive conditionals (per rule 3 of "Execution in ten rules") and will both be evaluated after the HITL is answered. Only the one matching the response will execute.

9. **State transition on block**: The transition to "Blocked" state occurs in the fallback flow before termination, reflecting the requirement to transition before terminating.

10. **Execution order**: The program follows the requirement's sequence: require first, then ask (with fallback for failure), then conditional delegations, then final emission.
