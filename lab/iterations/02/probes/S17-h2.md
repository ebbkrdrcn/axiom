# go_harness DSL for Test Suite Delegation

## DSL Code

```
DELEGATE test-suite
VERIFY test-suite
WHEN test-suite.accepted
  → TRANSITION "Review"
WHEN test-suite.rejected
  → TRANSITION "Debugging"
  → DELEGATE diagnosis
```

## Assumptions

1. **Work identifier for delegation**: The test suite work is identified as `test-suite`. The requirement says "delegate the test suite" but does not specify the exact identifier name. I chose `test-suite` as a descriptive identifier following naming conventions (letters, digits, `-`, `_`). Other choices like `tests`, `test`, or `run-tests` would be equally valid.

2. **Verification subject matches delegation**: The same identifier `test-suite` is used in both `DELEGATE` and `VERIFY` statements. This associates the verification with the work just delegated, as the requirement implies "verify it" referring to what was just delegated.

3. **Test pass/fail maps to accepted/rejected**: The requirement uses "pass" and "fail" language. In the DSL, `VERIFY` only produces outcomes `accepted` or `rejected` (never `passed`, `failed`, etc., per rule V6). I mapped "tests pass" to `test-suite.accepted` and "tests fail" to `test-suite.rejected`.

4. **Diagnosis work identifier**: The requirement says "delegate a diagnosis" but does not specify the identifier. I chose `diagnosis` as the work name. Other names like `debug`, `diagnose`, or `investigate` would be equally valid.

5. **No loop or concurrency**: The requirement describes a linear sequence of steps with no repetition or parallelism. I wrote the DSL without `LOOP` or `FORK` constructs, meaning execution runs once through these statements and then ends normally.

6. **No fallback on missing HITL response**: No human interaction (`HITL`) is needed for this requirement. All decisions (pass/fail path) are determined by `VERIFY`.

7. **No initial state specified**: The requirement does not specify what the process state is before these statements run. The `TRANSITION` statements set the state when reached; no initial state is set.

8. **Execution ends after these statements**: The requirement implies these are the complete process steps needed. Execution will end normally after the final `WHEN` statements without further `STOP` or loop constructs.
