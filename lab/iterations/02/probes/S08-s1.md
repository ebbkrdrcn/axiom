## 1. What happens at `REQUIRE staging-credentials`?

> The runtime determines the item cannot be obtained, and there is no `FALLBACK` → Execution ends, as with `STOP`.

- Because there is no `→ FALLBACK` attached to this `REQUIRE`, execution **ends immediately, as with `STOP`** (rule from the `REQUIRE` table; consistent with `STOP`'s effect that "no further statement runs anywhere").
- `REQUIRE` establishes no outcome, so no outcome is recorded for `staging-credentials`.

## 2. Is `DELEGATE deployment` executed?

No. Execution ended at the `REQUIRE` (treated as with `STOP`) before reaching the next statement. Per rule 2 of "Execution in ten rules," statements run one at a time in order and each finishes before the next starts; since the `REQUIRE` never completes (it ends the whole execution instead of continuing), `DELEGATE deployment` is never reached and never runs.

## 3. Is `EMIT deployment-log` executed?

No, for the same reason. `EMIT deployment-log` is even further down the same top-level sequential flow than `DELEGATE deployment`; since execution already ended at the `REQUIRE`, no later statement in the program runs.
