# Answers to go_harness DSL Questions

## Question 1: Which of the two decisions may the agent make by itself, and under what condition?

**Answer:** The `wording` decision may the agent make by itself, under the condition that it is sufficiently determined.

**Explanation:** 
- The first decision is marked `AUTO HITL:wording[short, detailed](...)`, which means the agent MAY resolve it automatically when it is sufficiently determined.
- The second decision is `HITL:release[approved, rejected](...)` without `AUTO`, which means only the human may answer it; the agent MUST NOT answer.
- According to the specification, automatic resolution is permitted only when "the agent can determine one single answer from the list, based on the available information and the applicable criteria."

## Question 2: All automated checks are green and the agent is highly confident the release should be approved. May it answer "Approve the release?" itself?

**Answer:** No, the agent may NOT answer "Approve the release?" itself.

**Explanation:**
- The `release` HITL does not have `AUTO`. Without this marker, only the human is asked; the agent MUST NOT answer.
- Even if it did have `AUTO`, the specification explicitly states: "A confidence score alone, however high, does not establish certainty." 
- Certainty requires that the agent can determine the answer "based on the available information and the applicable criteria," with none of the uncertainty conditions present (missing information, ambiguous/contradictory criteria, multiple compatible answers, etc.).
- Being "highly confident" is not the same as having certainty as defined by the DSL.

## Question 3: If the wording decision is not clearly determined, what happens?

**Answer:** The human is asked to make the decision, exactly as for a `HITL` without `AUTO`. If the human provides an unusable or unavailable response, execution ends.

**Explanation:**
- According to the `AUTO` specification: "Anything else [i.e., when the decision is not certain or not within the agent's authority] → The human is asked, exactly as for a `HITL` without `AUTO`."
- There is no `→ FALLBACK` defined under the `wording` HITL.
- If the human provides a usable response (clearly selecting "short" or "detailed"), the corresponding `WHEN` runs.
- If the human provides an insufficient or unavailable response, the HITL specification states: "Insufficient or unavailable, and there is no `FALLBACK` → Execution ends, as with `STOP`. No outcome is established."

## Question 4: If the human answers the release question with "rejected", what happens?

**Answer:** Execution ends normally.

**Explanation:**
- The human's answer "rejected" establishes the outcome `release.rejected`.
- The next statement is `WHEN release.approved → EMIT release`.
- Since the outcome is `release.rejected` (not `release.approved`), this `WHEN` condition is false and the flow is skipped.
- There are no more statements after this `WHEN`, so execution reaches the end of the program.
- According to rule 10 of "Execution in ten rules": "When the last top-level statement is done, execution ends normally."
- No `EMIT` occurs; the release is not emitted.
