# DSL for Test Suite Process

## DSL Program

```
DELEGATE test-suite
VERIFY test-suite
WHEN test-suite.accepted
  → TRANSITION "Review"
WHEN test-suite.rejected
  → TRANSITION "Debugging"
  → DELEGATE diagnosis
```

## Assumptions

1. **Name of the delegated work:** The requirement says "delegate the test suite" but does not specify an identifier for this work. I assumed the name `test-suite`.

2. **Name of the diagnosis work:** The requirement says "delegate a diagnosis" but does not specify an identifier. I assumed the name `diagnosis`.

3. **Result verification subject:** I assumed that the `VERIFY` statement operates on the same result from the `DELEGATE test-suite`, hence `VERIFY test-suite`. The requirement does not explicitly state they are the same, but this is the natural reading.

4. **Order of operations when tests fail:** The requirement states "move to state 'Debugging' and delegate a diagnosis." I assumed these two actions occur in the order written: first `TRANSITION "Debugging"`, then `DELEGATE diagnosis`. The specification allows both to be in the same flow, and no timing relationship is specified, so this order is reasonable.

5. **No error recovery or looping:** The requirement does not mention retrying, looping, or fallback behavior. I assumed the process runs once through to completion without repetition or exception handling.
