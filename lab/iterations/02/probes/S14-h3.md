# Execution Trace and Final State

## Step-by-step Execution

```trace
1. FORK -> branches started
2. DELEGATE unit-tests -> done
3. VERIFY unit-tests -> outcome unit-tests.accepted
4. DELEGATE integration-tests -> done
5. VERIFY integration-tests -> outcome integration-tests.rejected
6. JOIN -> joined
7. WHEN unit-tests.accepted -> true: run flow
8. TRANSITION "Ready" -> state = "Ready"
9. WHEN integration-tests.rejected -> true: run flow
10. TRANSITION "Debugging" -> state = "Debugging"
11. (end of program) -> end
```

## Final State

**Debugging**

## Explanation

The FORK statement starts two concurrent branches:
- **Branch 1:** DELEGATE unit-tests, then VERIFY unit-tests (establishes unit-tests.accepted)
- **Branch 2:** DELEGATE integration-tests, then VERIFY integration-tests (establishes integration-tests.rejected)

Since integration-tests finishes later, both branches eventually complete. The JOIN waits for both to finish before proceeding.

After the JOIN, both WHEN conditions are evaluated:
- `WHEN unit-tests.accepted` is true, so `TRANSITION "Ready"` executes, setting state to "Ready"
- `WHEN integration-tests.rejected` is true, so `TRANSITION "Debugging"` executes, setting state to "Debugging"

According to the specification (line 306): "The process has exactly one current state. Each TRANSITION replaces it; the most recently executed one wins."

Therefore, the final state is **"Debugging"** because it is the last TRANSITION executed.
