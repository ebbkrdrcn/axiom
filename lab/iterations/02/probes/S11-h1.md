# Execution Analysis: go_harness DSL Program

## Validation Result

**This program is INVALID and cannot be executed.**

### Violation Detected: Rule V3

The program violates validity rule V3:

> "`BREAK` is inside a `FORK` branch, and the `LOOP` it would leave is outside that branch"

### Explanation

In the given program:

```
LOOP:review
  FORK
    → DELEGATE security-review
        VERIFY security-review
        WHEN security-review.rejected
          → BREAK
    → DELEGATE docs-review
        VERIFY docs-review
  JOIN
  TRANSITION "Reviewed"
EMIT review-summary
```

The `BREAK` statement is located inside the first `→` branch of the `FORK`. Specifically:
- `BREAK` is nested under `WHEN security-review.rejected`
- This `WHEN` is nested under the first `→ DELEGATE security-review` item
- This `→` item is a branch of `FORK`

The `LOOP:review` that `BREAK` would attempt to leave is **outside** the `FORK` branch—it is at the top level, containing the entire `FORK` construct.

### Why This Violates the Rules

From the specification:

- The `BREAK` section states: "`BREAK` is **INVALID** inside a `FORK` branch unless the `LOOP` it leaves is also inside that branch (V3)."
- A branch is defined as: "the `→` statement plus the lines nested under it."
- The innermost `LOOP` that encloses `BREAK` (`LOOP:review`) is outside the branch.

### Consequence

Per the "Executing a program" procedure:

> "1. **Validate first.** Check rules V1–V10. If any is broken, do not execute. Report each broken rule by its number."

Therefore, execution MUST NOT proceed. The program must be rejected as a whole.

## Corrected Program (For Reference)

If the intent was to break from the loop based on the security review outcome, the structure should be:

```
LOOP:review
  FORK
    → DELEGATE security-review
        VERIFY security-review
    → DELEGATE docs-review
        VERIFY docs-review
  JOIN
  WHEN security-review.rejected
    → BREAK
  TRANSITION "Reviewed"
EMIT review-summary
```

This is valid because the `WHEN` (and its `BREAK`) is outside the `FORK`, so the `BREAK` can safely leave the loop.
