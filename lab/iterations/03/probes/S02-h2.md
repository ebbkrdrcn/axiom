# DSL for the Requirement

## DSL Program

```
LOOP:build
  DELEGATE implementation
  VERIFY implementation
  WHEN implementation.accepted
    → BREAK
  WHEN implementation.rejected
    → DELEGATE correction
EMIT source-code
```

## Assumptions Made

1. **Work item name**: The delegated work is named "implementation" (not specified in the requirement).

2. **Correction work name**: The correction work is named "correction" (not specified in the requirement).

3. **Output artifact name**: The emitted artifact is named "source-code" (given in the requirement).

4. **VERIFY outcomes**: The VERIFY statement produces exactly two possible outcomes: `implementation.accepted` (verification accepts) and `implementation.rejected` (verification rejects).

5. **Loop continuation**: After delegating correction, the loop automatically repeats from the first statement (the DELEGATE implementation) due to reaching the end of the loop body. No explicit LOOP restart is needed.

6. **No loop limit**: The loop continues indefinitely until the verification accepts. There is no maximum iteration count or timeout mechanism.

7. **Correction does not affect the outcome**: The DELEGATE correction statement is a side effect; it establishes no outcome and does not modify the `implementation` outcome. The next iteration's VERIFY will re-evaluate the implementation and may produce a different outcome.

8. **Sequential flow**: All statements in the loop body and after run sequentially, with no concurrent branches (no FORK).
