# DSL Program

```
LOOP:implementation
  DELEGATE implementation
  VERIFY implementation
  WHEN implementation.accepted
    → BREAK
  WHEN implementation.rejected
    → DELEGATE correction
EMIT source-code
```

# Assumptions

1. **Work item names**: The requirement uses "the implementation" and "a correction" as generic terms. I assumed these are represented by the identifiers `implementation` and `correction` in the DSL.

2. **Loop control**: The requirement says "leave the repetition" when verification accepts. I interpreted this as exiting the loop via `BREAK`, not repeating the verification step.

3. **Repeat behavior**: The requirement says "repeat from the start" after delegating a correction. I assumed this means allowing the loop to naturally continue to its next iteration, which restarts from the first statement (`DELEGATE implementation`), without an explicit `BREAK`.

4. **Verification outcomes**: I assumed that `VERIFY implementation` establishes exactly one outcome per execution: either `implementation.accepted` or `implementation.rejected`, as defined in the DSL specification.

5. **Correction handling**: After delegating a correction, the requirement specifies only that the process repeats "from the start". I assumed the delegated correction work is completed before the loop restarts, and no additional verification of the correction itself is required before the next implementation delegation.

6. **No fallback needed**: The requirement does not mention failure handling. I assumed that if verification cannot determine an outcome, the program fails (execution ends), rather than requiring a fallback flow.

7. **Output artifact**: The requirement says "emit source-code". I interpreted this as a single emission event with the identifier `source-code`, representing the final output. The DSL does not specify how or where this is stored or transported.

8. **Loop termination is guaranteed**: The requirement assumes that eventually `VERIFY implementation` will establish `implementation.accepted`. I made no assumption about the number of iterations required.

9. **No binding required**: The requirement does not mention entities or external data dependencies. I assumed no bindings are needed at the top of the program.

10. **Sequential execution within loop**: All statements in each loop iteration execute sequentially. The delegation of implementation, its verification, and conditional delegation of correction follow one after the other within each iteration.
