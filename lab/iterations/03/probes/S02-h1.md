# DSL Solution for S02

## DSL

```
LOOP:implementation-loop
  DELEGATE implementation
  VERIFY implementation
  WHEN implementation.accepted
    → BREAK
  WHEN implementation.rejected
    → DELEGATE correction
EMIT source-code
```

## Assumptions

1. **Work item name**: The implementation is referred to as "implementation". The requirement does not specify a particular name, so I chose a descriptive identifier that makes the code's meaning clear.

2. **Correction work**: The "correction" is delegated as a separate work item using `DELEGATE correction`. The DSL does not specify how the correction is performed—only that it is delegated to an actor. A `VERIFY correction` is not required by the specification.

3. **Loop name**: The loop is labeled "implementation-loop" as a descriptive label. Per the DSL rules, the name is only a label and no statement refers to it.

4. **Outcome names**: The outcomes used in `WHEN` statements are `accepted` and `rejected`, which are the only valid outcomes produced by `VERIFY` (rule V6).

5. **No failure handling**: No `FALLBACK` is included. The requirement does not mention what should happen if `VERIFY` or `DELEGATE` operations fail. If failure handling were needed, a `FALLBACK` could be added to either operation.

6. **Natural loop termination**: After `DELEGATE correction` completes, the loop body ends and execution automatically restarts from the first statement. The requirement's phrase "repeat from the start" describes this natural loop behavior; no explicit `BREAK` is needed.

7. **Output artifact name**: The final output is named "source-code" as a straightforward identifier for the emitted artifact. The requirement does not specify the name.

8. **No explicit program termination**: After `EMIT source-code` completes, execution ends naturally (rule 10: "When the last top-level statement is done, execution ends normally"). No explicit `STOP` is required.

## How it satisfies the requirement

- **"Repeatedly"**: The `LOOP:implementation-loop` statement repeats the body.
- **"Delegate the implementation, then verify it"**: `DELEGATE implementation` followed by `VERIFY implementation`.
- **"If the verification accepts it, leave the repetition"**: `WHEN implementation.accepted → BREAK` exits the loop.
- **"If the verification rejects it, delegate a correction and then repeat from the start"**: `WHEN implementation.rejected → DELEGATE correction` delegates correction work; the loop then naturally repeats from the first statement.
- **"After the repetition ends, emit source-code"**: `EMIT source-code` executes after the loop exits via `BREAK`.
