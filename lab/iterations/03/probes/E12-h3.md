# Validity Analysis of DSL Snippets

## Snippet A

```
t1:Task = TASK-0100
LOOP:work
  a1:ADR = t1.adr
  VERIFY t1
  WHEN t1.accepted
    → BREAK
```

**Answer: INVALID**

**Rules broken:** V11

**Explanation:** 
Line 3 contains a binding `a1:ADR = t1.adr`, but this binding is indented (inside the LOOP body). According to V11, bindings are INVALID if they are indented. V11 states: "a binding is indented, or follows a statement that is not a binding, or binds a name that is already bound, or its relation starts from a name not bound on an earlier line". Bindings MUST appear at the top of the program, unindented, before every other statement.

## Snippet B

```
a1:ADR = t1.adr
t1:Task = TASK-0100
VERIFY a1
```

**Answer: INVALID**

**Rules broken:** V11

**Explanation:**
Line 1 contains a binding `a1:ADR = t1.adr` that references `t1` in the relation, but `t1` is not bound on an earlier line—it is bound for the first time on line 2. According to V11, a binding is INVALID if "its relation starts from a name not bound on an earlier line". Bindings must reference only names that have already been bound.

## Snippet C

```
t1:Task = TASK-0102
TRANSITION t1 "Done"
```

**Answer: VALID**

**Rules broken:** None

**Explanation:**
This program is well-formed and violates no validity rules (V1-V12). Both lines are syntactically correct: line 1 is a valid binding at the top, and line 2 is a valid entity transition statement. Although the transition will fail at execution time (TASK-0102 is in status `Todo`, and the Task Definition does not permit a transition from `Todo` to `Done`), this is an execution failure, not a validity error. According to the entity model: "A transition that the Definition does not permit is not INVALID: the program is well-formed, and the transition fails when it is executed."

## Snippet D

```
t1:Task = TASK-0100
HITL:t1[approved, rejected]("Done?")
TRANSITION t2 "Done"
```

**Answer: INVALID**

**Rules broken:** V12 (two violations)

**Explanation:**
Line 2 violates V12 by using the bound name `t1` as a HITL name. V12 states: "a bound name is used as a `HITL` name". A HITL name must not conflict with a bound entity name.

Line 3 violates V12 by using `t2` in a transition statement when `t2` has not been bound. V12 also states: "`TRANSITION <name> "<status>"` uses a name that is not bound". The name `t2` must be bound before it can be used in a transition.
