# Program for ADR-0101 Review and Decision

## DSL Program

```text
adr:ADR = ADR-0101
VERIFY adr
HITL:decision[approved, rejected]("Should ADR-0101 be accepted?")
  → FALLBACK
      → TRANSITION "Waiting"
      → STOP
WHEN decision.approved
  → TRANSITION adr "Accepted"
WHEN decision.rejected
  → TRANSITION adr "Rejected"
```

## Explanation

1. **Binding** (`adr:ADR = ADR-0101`): Binds the ADR-0101 entity to the name `adr` for use in the program.

2. **Verification** (`VERIFY adr`): Evaluates ADR-0101 against the ADR verification criteria. For ADR-0101, which contains Context, Decision, and Consequences sections with clear content, this establishes `adr.accepted`.

3. **Human Decision** (`HITL:decision[approved, rejected]("Should ADR-0101 be accepted?")`): Asks the human to choose between `approved` and `rejected`. The question includes the entity identity (ADR-0101) to satisfy the precondition requirement for entity transitions.

4. **Fallback Handler**: If the human gives no usable answer (insufficient or unavailable response), the FALLBACK runs, setting the process state to "Waiting" and stopping execution.

5. **Approval Flow** (`WHEN decision.approved`): If the human approves, transitions ADR-0101 to "Accepted". This satisfies the precondition `human: approved`, and combined with the prior `VERIFY adr` establishing `adr.accepted`, the precondition `verified: accepted; human: approved` for the Proposed → Accepted transition is met.

6. **Rejection Flow** (`WHEN decision.rejected`): If the human rejects, transitions ADR-0101 to "Rejected". This satisfies the precondition `human: rejected` for the Proposed → Rejected transition.

## Assumptions

1. **Entity Existence**: ADR-0101 exists in the environment and can be resolved by its identity.

2. **Entity Type**: ADR-0101 is of type ADR and is structurally valid according to the ADR Template.

3. **Initial Status**: ADR-0101 is in the "Proposed" status (the only non-terminal status from which the required transitions can be made).

4. **Verification Outcome**: The VERIFY operation on ADR-0101 will successfully determine an outcome. Given that ADR-0101 contains all required sections (Context, Decision, Consequences) with clear content, it is expected to establish `adr.accepted`.

5. **Human Response**: The human will eventually provide a response to the HITL question; if they do not, the FALLBACK handles this by setting state to "Waiting" and stopping.

6. **Precondition Satisfaction**: The question "Should ADR-0101 be accepted?" contains the entity identity, satisfying the requirement that the `human: <answer>` precondition verification checks the question for entity identity.

7. **Data Persistence**: The verification outcome (`adr.accepted`) established by VERIFY persists and remains valid when the TRANSITION statements are reached, as no external changes occur between these operations.

8. **Representation Update**: The ADR's status is recorded in its authoritative representation (the Markdown file) upon successful transition.
