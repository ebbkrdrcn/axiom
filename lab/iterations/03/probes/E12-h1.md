# E12 Analysis

## Snippet A

**INVALID**

Breaks: **V11**

**Reason:** The binding `a1:ADR = t1.adr` is indented (it is the first line inside the `LOOP:work` block). According to V11, a binding MUST be written at the top of the program, before every other statement, without indentation. A binding appearing inside any scope is invalid.

---

## Snippet B

**INVALID**

Breaks: **V11**

**Reason:** The binding `a1:ADR = t1.adr` appears first, but it references `t1.adr`. At this point, `t1` has not yet been bound. According to V11, a relation binding's source name must be bound on an earlier line. Since `t1` is bound only on the second line, the first binding cannot be satisfied, violating V11.

---

## Snippet C

**VALID**

**Reason:** All validity rules are satisfied:
- The binding `t1:Task = TASK-0102` is at the top, unindented (V11 ✓)
- The `TRANSITION t1 "Done"` uses a bound name (V12 ✓)
- No other rules are violated

Note: At execution time, this transition will fail because TASK-0102's status is `Todo` and the Task Definition does not permit a transition directly from `Todo` to `Done`. However, that is an execution failure, not a validity error. The program is well-formed and would run `FALLBACK` or end (per execution rule 12) if no `FALLBACK` is attached.

---

## Snippet D

**INVALID**

Breaks: **V12, V12**

**Reason:** Two separate violations of V12:

1. `HITL:t1[approved, rejected]("Done?")` uses `t1` as the HITL name, but `t1` is a bound name (bound on line 1 as `t1:Task = TASK-0100`). V12 states: "a bound name is used as a `HITL` name" is invalid.

2. `TRANSITION t2 "Done"` uses the name `t2`, which is not bound anywhere in the program. V12 states: "`TRANSITION <name> "<status>"` uses a name that is not bound" is invalid.
