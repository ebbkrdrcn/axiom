# Answers

## Snippet 1

```text
HITL:deploy("Deploy to production?") AUTO
WHEN deploy.yes
  → EMIT deployment
```

**VALID**

- The `HITL` line matches the required form exactly: `HITL[:<name>]("<message>") [AUTO]`, i.e. grammar rule `hitl = "HITL" , [ ":" , identifier ] , "(" , string , ")" , [ "AUTO" ] , NL , ...`. `AUTO` is written directly after the closing parenthesis, on the same line, as required by the `AUTO` syntax rule ("`AUTO` is written directly after the closing parenthesis of `HITL(...)`, on the same line.").
- The name `deploy` is used because a `WHEN deploy.yes` follows, which is exactly the case the spec allows a name for: "`<name>` names the decision. The response establishes the outcome `<name>.<answer>`, where `<answer>` is one of the answers tested by the `WHEN <name>.<answer>` constructs that follow." The spec does not restrict `<answer>` to a fixed vocabulary (e.g. it need not be "approved"/"declined"); `yes` is a valid identifier used consistently as the answer tested afterward.
- `WHEN deploy.yes` is a statement at the indentation of `HITL` (the normal flow, per "Statements after the `HITL` construct, at the indentation of `HITL`, are the normal flow"), with a well-formed condition `<identifier>.<identifier>` (`deploy.yes`).
- `→ EMIT deployment` is correctly indented as the single item of the `WHEN` flow, and `EMIT <argument>` is a valid simple statement.

No rule in the specification is violated.

## Snippet 2

```text
DELEGATE implementation AUTO
VERIFY implementation
```

**INVALID**

- This is the exact case the specification calls out as invalid: "Invalid, because `AUTO` applies only to `HITL`: `DELEGATE implementation AUTO`."
- It also violates the grammar: the `simple` production for `DELEGATE` is `"DELEGATE" , argument , NL` — there is no slot for a trailing `AUTO` token, and `argument = identifier | string`, so `implementation AUTO` cannot be parsed as a single argument (it also isn't a string).
- Further supported by: "`AUTO` is not a statement of its own and applies to no other statement. `AUTO` applies only to `HITL`."

## Snippet 3

```text
AUTO HITL:deploy("Deploy to production?")
WHEN deploy.yes
  → EMIT deployment
```

**INVALID**

- `AUTO` must appear "directly after the closing parenthesis of `HITL(...)`, on the same line" — i.e. after the `HITL(...)` construct, not before it. Here `AUTO` precedes `HITL`, which reverses the required order.
- The grammar confirms this: `hitl = "HITL" , [ ":" , identifier ] , "(" , string , ")" , [ "AUTO" ] , NL , ...` places the optional `"AUTO"` token only after `HITL(...)"`. A line beginning with the token `AUTO` followed by `HITL:...` does not match the `hitl` production (nor any other statement production, since `AUTO` is not itself a keyword that starts a statement — "`AUTO` is not a statement of its own").
- Since the program as written does not conform to the grammar, it is not well-formed and must be rejected as a whole (per "Programs, fragments, and validity": a rule violation means the program "must be rejected as a whole; it is not executed with the offending part skipped").

## Snippet 4

```text
AUTO
  WHEN decision.uncertain
    → HITL("Approve?")
```

**INVALID**

- This matches the specification's own explicit invalid example verbatim: "Also invalid, because `AUTO` never contains a flow and uncertainty is not a condition: `AUTO` / `WHEN decision.uncertain` / `→ HITL("Approve?")`."
- Supporting rules: "`AUTO` is not a control-flow container. It does not contain `WHEN`, `→`, or an arbitrary flow." and "Uncertainty is not a DSL condition, state, variable, or keyword," so `decision.uncertain` cannot be a valid `WHEN` condition either.
- Grammatically, `AUTO` is not a keyword that begins any `statement` production (`loop | when | fork | hitl | simple`) and never takes an `INDENT`/`block`/`flow`, so a `AUTO` line followed by an indented `WHEN` block cannot be derived from the grammar at all.

# Notes on assumptions

- The specification does not enumerate a fixed set of permissible `HITL` answer names (e.g. it uses "approved"/"declined" only as an example). I assumed any well-formed identifier consistently used as `<name>.<answer>` in a following `WHEN` (such as `deploy.yes` in Snippet 1) is acceptable, since the spec defines `<answer>` only as "one of the answers tested by the `WHEN <name>.<answer>` constructs that follow," with no further restriction.
- For Snippets 2–4, the specification is fully explicit (either by a direct "Invalid" example or by unambiguous grammar/rule text), so no additional assumptions were needed there.
