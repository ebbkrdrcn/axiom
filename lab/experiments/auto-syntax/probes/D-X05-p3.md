# Validity Analysis of go_harness Snippets

## Snippet 1

```text
AUTO
HITL:deploy("Deploy to production?")
WHEN deploy.yes
  → EMIT deployment
```

**Verdict: VALID**

Rule cited: Syntax → Grammar, `hitl = [ "AUTO", NL ], "HITL", [ ":", identifier ], "(", string, ")", NL, ...` and the `AUTO` section: "`AUTO` is written on its own line directly before a `HITL`, at the same indentation. It marks only the `HITL` on the immediately following line as automatically resolvable."

Here `AUTO` occupies its own line and is immediately followed, at the same indentation, by a well-formed `HITL:<name>("<message>")` statement (`HITL:deploy("Deploy to production?")`), matching the required form exactly. The subsequent `WHEN deploy.yes` is a syntactically valid condition (`<identifier>.<identifier>`, per the Conditional Flow section: "`<condition>` has the form `<identifier>.<identifier>`"), and it appears at the indentation of the `HITL` construct, i.e., as the next statement after `HITL` — consistent with "After the decision is made, by the agent or by the human, execution continues with the statement after the `HITL` construct." The `→ EMIT deployment` item is a correctly indented single-item flow under `WHEN` (grammar: `when = "WHEN", condition, NL, INDENT, flow, DEDENT`). Nothing in the spec restricts the literal name of the answer identifier (`yes`) — `<name>.<answer>` is established by whatever the `WHEN` conditions test, so `deploy.yes` is an acceptable answer name. No rule is violated.

## Snippet 2

```text
AUTO
DELEGATE implementation
VERIFY implementation
```

**Verdict: INVALID**

Rule cited: `AUTO` section: "`AUTO` is not a statement of its own and applies to no other statement. `AUTO` applies only to `HITL`," together with the explicit worked example given in the spec: "Invalid, because `AUTO` applies only to `HITL`: `AUTO` / `DELEGATE implementation`." Also the Scope/Syntax rule: "`AUTO` (only on the line directly before a `HITL`)," and "An `AUTO` line that is not immediately followed by a `HITL` is invalid."

This snippet is structurally identical to the specification's own explicit invalid example: `AUTO` is immediately followed by `DELEGATE implementation`, not by a `HITL` statement. Since `AUTO` may only ever mark the `HITL` on the line directly following it, and here the following statement is `DELEGATE`, the program is not well-formed. Per "Programs, fragments, and validity," a program violating a "must not" / "invalid" rule "must be rejected as a whole."

## Snippet 3

```text
AUTO HITL:deploy("Deploy to production?")
WHEN deploy.yes
  → EMIT deployment
```

**Verdict: INVALID**

Rule cited: `AUTO` section: "`AUTO` is written on its own line directly before a `HITL`, at the same indentation." Grammar: `hitl = [ "AUTO", NL ], "HITL", ...` — the grammar requires `AUTO` to be followed by a newline (`NL`) before the `HITL` token appears. Also Syntax table: "`AUTO` (only on the line directly before a `HITL`)" — implying `AUTO` is its own statement/line, distinct from the `HITL` line.

In this snippet, `AUTO` and `HITL:deploy("Deploy to production?")` are written on the **same line** ("`AUTO HITL:deploy(...)`"), rather than `AUTO` occupying its own line immediately preceding a separate `HITL` line. This does not match the required grammar production `[ "AUTO", NL ], "HITL", ...`, which mandates a line break between `AUTO` and `HITL`. The construct as written corresponds to no valid statement form at all (it is neither a bare `AUTO` line, nor a bare `HITL` line, nor any other listed statement form in the Statement table), so the program is not well-formed and must be rejected as a whole.

## Snippet 4

```text
AUTO
  WHEN decision.uncertain
    → HITL("Approve?")
```

**Verdict: INVALID**

Rule cited: `AUTO` section, explicit worked example: "Also invalid, because `AUTO` never contains a flow and uncertainty is not a condition: `AUTO` / `  WHEN decision.uncertain` / `    → HITL("Approve?")`." Supporting rules: "`AUTO` is not a control-flow container. It does not contain `WHEN`, `→`, or an arbitrary flow," and "Uncertainty is not a DSL condition, state, variable, or keyword."

This snippet is verbatim the specification's own explicit invalid example. `AUTO` is shown here with an indented child (`WHEN decision.uncertain`), treating it as a scoped, containing construct — but the grammar for `AUTO` only ever allows `[ "AUTO", NL ], "HITL", ...` with no `INDENT`/`block` under `AUTO` itself. Additionally, `decision.uncertain` attempts to use "uncertainty" as a `WHEN` condition, which the spec explicitly forbids ("Uncertainty is not a DSL condition, state, variable, or keyword... The DSL runtime determines uncertainty as part of automatic decision resolution," not something a program can test via `WHEN`). Both defects independently make the program not well-formed; per "Programs, fragments, and validity," it must be rejected as a whole rather than partially executed.
