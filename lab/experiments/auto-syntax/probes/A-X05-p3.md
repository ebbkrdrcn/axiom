# Task: Validity of DSL snippets

## Snippet 1

```text
AUTO HITL:deploy("Deploy to production?")
WHEN deploy.yes
  → EMIT deployment
```

**VALID**

- The `HITL` line matches the grammar production `hitl = [ "AUTO" ] , "HITL" , [ ":" , identifier ] , "(" , string , ")" , NL , ...`: `AUTO` appears directly before `HITL`, on the same line, exactly as required ("`AUTO` is written directly before `HITL`, on the same line. It marks that one `HITL` as automatically resolvable.", section **AUTO**; syntax line `AUTO HITL:<name>("<message>")`).
- `deploy` is a valid `<name>` (identifier: letters/digits/`-`/`_`, starts with a letter — section **Identifier**).
- The following `WHEN deploy.yes` tests `<name>.<answer>` = `deploy.yes`, which is exactly the mechanism described for `HITL`: "The response establishes the outcome `<name>.<answer>`, where `<answer>` is one of the answers tested by the `WHEN <name>.<answer>` constructs that follow" (section **HITL**). The condition form `<identifier>.<identifier>` is satisfied (section **Conditional Flow** / grammar `condition = identifier , "." , identifier`).
- The `→ EMIT deployment` item is a well-formed `WHEN` flow item (`item = "→" , statement , ...`), and `EMIT` takes an identifier argument as required (`simple` grammar rule).
- No `FALLBACK` is present, but `FALLBACK` is optional in the grammar (`[ INDENT , "→" , "FALLBACK" , ... ]` is bracketed, i.e. optional).

No rule in the specification is violated, so the snippet is well-formed.

## Snippet 2

```text
AUTO DELEGATE implementation
VERIFY implementation
```

**INVALID**

- The specification gives this exact pattern as an explicit counter-example: "Invalid, because `AUTO` applies only to `HITL`: `AUTO DELEGATE implementation`" (section **AUTO**).
- This is also confirmed by the general rule: "`AUTO` is not a statement of its own and applies to no other statement. `AUTO` applies only to `HITL`." (section **AUTO**).
- The grammar has no production allowing `AUTO` before `DELEGATE`; the only place `AUTO` may appear is inside the `hitl` production, immediately before the `HITL` keyword.

Since the specification explicitly labels this construct "invalid," the program containing it "is not well-formed. It must be rejected as a whole" (section **Programs, fragments, and validity**).

## Snippet 3

```text
HITL:deploy("Deploy to production?") AUTO
WHEN deploy.yes
  → EMIT deployment
```

**INVALID**

- The syntax table specifies the statement form as `[AUTO] HITL[:<name>]("<message>")` — i.e. `AUTO`, if present, must come *before* `HITL` (section **Syntax → Statement**).
- The grammar is explicit about ordering: `hitl = [ "AUTO" ] , "HITL" , [ ":" , identifier ] , "(" , string , ")" , NL , ...` — `AUTO` is the first optional token of the production, not a trailing modifier.
- Section **AUTO** states: "`AUTO` is written directly before `HITL`, on the same line." Placing `AUTO` after the closing `)` of the `HITL` call does not match this required position.

There is no grammar rule that allows a trailing `AUTO` after a `HITL(...)` call, so this line cannot be derived from the `hitl` production (nor any other), making the program not well-formed (section **Programs, fragments, and validity**).

## Snippet 4

```text
AUTO
  WHEN decision.uncertain
    → HITL("Approve?")
```

**INVALID**

- This is (up to the identifier/string text) the specification's own explicit invalid example: "Also invalid, because `AUTO` never contains a flow and uncertainty is not a condition: `AUTO` / `  WHEN decision.uncertain` / `    → HITL("Approve?")`" (section **AUTO**).
- Supporting rules: "`AUTO` is not a control-flow container. It does not contain `WHEN`, `→`, or an arbitrary flow." and "Uncertainty is not a DSL condition, state, variable, or keyword." (section **AUTO**).
- Grammatically, `AUTO` only ever occurs as the optional leading token inside the `hitl` production (`[ "AUTO" ] , "HITL" , ...`); there is no production in which bare `AUTO` heads an indented block (`INDENT ... DEDENT`) containing a `WHEN` statement. A bare `AUTO` line followed by an indented block cannot be derived from the grammar at all.

Since the specification directly calls this pattern invalid and no grammar rule admits it, the program is not well-formed (section **Programs, fragments, and validity**).
