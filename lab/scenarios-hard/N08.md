# N08 — Execution: nested loops with a WHEN at the end of each body

## Task
Execute this program.

```text
LOOP:outer
  DELEGATE batch
  LOOP:inner
    DELEGATE item
    VERIFY item
    WHEN item.accepted
      → BREAK
  VERIFY batch
  WHEN batch.accepted
    → BREAK
  WHEN batch.rejected
    → TRANSITION "Retry"
EMIT report
```

Events: the `VERIFY item` results, in order, are `rejected`, `accepted`, `accepted`. The `VERIFY batch` results, in order, are `rejected`, `accepted`.

Answer with: (1) the validity verdict (VALID, or INVALID with every broken rule number); (2) if VALID, the execution trace in the specification's trace format; (3) the final status of every bound entity and which entity files changed, and how (if any entities are bound); (4) the final process state. Also state how many times `DELEGATE batch` and `DELEGATE item` run.

## Expected
- D1 VALID.
- D2 After the false `WHEN item.accepted` (last statement of the inner body) the inner loop starts again; it does not continue with `VERIFY batch`.
- D3 After `WHEN batch.rejected` runs (last statement of the outer body) the outer loop starts again.
- D4 `DELEGATE batch` runs 2 times; `DELEGATE item` runs 3 times; `EMIT report` runs once, at the end.
- D5 Final process state `Retry`.

### Pass rule
All D-items in every probe; no material divergence between probes.
