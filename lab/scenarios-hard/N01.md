# N01 — Execution: BREAK of a loop nested inside a FORK branch

## Task
Execute this program.

```text
FORK
  → LOOP:retry
      DELEGATE upload
      VERIFY upload
      WHEN upload.accepted
        → BREAK
  → DELEGATE docs
JOIN
WHEN upload.accepted
  → TRANSITION "Uploaded"
```

Events: the first `VERIFY upload` establishes `rejected`, the second establishes `accepted`. All delegated work is delivered.

Answer with: (1) the validity verdict (VALID, or INVALID with every broken rule number); (2) if VALID, the execution trace in the specification's trace format; (3) the final status of every bound entity and which entity files changed, and how (if any entities are bound); (4) the final process state. Also state how many times `DELEGATE upload` runs, and what the `BREAK` ends.

## Expected
- D1 VALID (the LOOP that BREAK leaves is inside the same branch; V3 is not broken).
- D2 `DELEGATE upload` runs 2 times; after the first (rejected) VERIFY the false WHEN is followed by the loop restarting.
- D3 BREAK ends only `LOOP:retry`; it does not end the FORK, the other branch, or the execution.
- D4 JOIN waits for both branches; then `WHEN upload.accepted` is true.
- D5 Final process state `Uploaded`.

### Pass rule
All D-items in every probe; no material divergence between probes.
