# ST07 — Stress authoring: ten-step requirement

Type: authoring

## Task
Write go_harness DSL for the following requirement:

"First the repository must be available; if it cannot be obtained, move to state "Blocked" and stop. Then repeatedly: delegate the implementation and, at the same time, delegate the documentation; wait for both; then verify the implementation. If the implementation is accepted, leave the repetition; otherwise delegate a correction and repeat. After the repetition, the agent may itself decide whether to release now or later when that is clearly determined; otherwise ask a human "Release now or later?". If now: emit release and move to state "Released". If later: move to state "Scheduled". If no usable answer is obtained: move to state "Waiting" and stop."

Output the DSL in a code block, then list every assumption you had to make.

## Expected
- D1 Linter VALID.
- D2 `REQUIRE repository` with FALLBACK (Blocked, STOP).
- D3 LOOP: FORK (implementation ‖ documentation), JOIN, VERIFY implementation, `WHEN …accepted → BREAK`, `WHEN …rejected → DELEGATE correction`.
- D4 After the loop: `AUTO HITL:<n>[now, later]("Release now or later?")` with FALLBACK (Waiting, STOP).
- D5 `WHEN <n>.now` → EMIT release then TRANSITION "Released"; `WHEN <n>.later` → TRANSITION "Scheduled".

### Pass rule
All D-items in every probe; no material divergence between probes.
