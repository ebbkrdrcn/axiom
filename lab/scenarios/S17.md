# S17 — Authoring: pass/fail wording

Type: authoring

## Task
Write go_harness DSL for the following requirement:

"Delegate the test suite, then verify it. If the tests pass, move to state "Review". If the tests fail, move to state "Debugging" and delegate a diagnosis."

Output the DSL in a code block, then list every assumption you had to make.

## Expected
- D1 Linter VALID.
- D2 DELEGATE x then VERIFY x (same identifier).
- D3 `WHEN x.accepted → TRANSITION "Review"`; `WHEN x.rejected → TRANSITION "Debugging"` then `DELEGATE diagnosis` (this order). There are no `passed`/`failed` outcomes.

### Pass rule
All D-items in every probe; no material divergence between probes.
