# N10 Analysis: go_harness DSL Validity

## Snippet A

```
LOOP:deploy
  DELEGATE deploy
  VERIFY deploy
  WHEN deploy.accepted
    → BREAK release
```

**INVALID**

**Broken rules:**
- **V1**: The line `→ BREAK release` does not match any valid statement form. According to the syntax rules, `BREAK` must stand alone followed by a newline: `( "JOIN" | "BREAK" | "WAIT" | "STOP" ) , NL`. The argument `release` is not permitted.

## Snippet C

```
FORK
  → VERIFY api
  → VERIFY ui
WHEN api.accepted
  → EMIT api-report
```

**INVALID**

**Broken rules:**
- **V10**: The `WHEN api.accepted` condition tests `api`, whose outcome is established by the first branch of the FORK via `VERIFY api`. Rule V10 requires that when a `WHEN` tests a subject that a branch of a `FORK` establishes, no `JOIN` of that `FORK` must exist between the `FORK` and the `WHEN`. Here, the `WHEN` directly follows the `FORK` without a `JOIN`, making outcomes from the concurrent branches untestable in this flow.

## Snippet E

```
t1:Task = TASK-0100
VERIFY t1
WHEN t1.accepted
  → TRANSITION t2 "Review"
```

**INVALID**

**Broken rules:**
- **V12**: The statement `TRANSITION t2 "Review"` uses the name `t2`, which is not bound anywhere in the program. Only `t1` is bound at the top of the program. Rule V12 explicitly forbids using a name in an entity transition that has not been bound.
