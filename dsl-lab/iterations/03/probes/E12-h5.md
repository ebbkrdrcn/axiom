**Broken rules:** V11

**Explanation:** The binding `a1:ADR = t1.adr` on line 3 is indented inside the LOOP body. Bindings must appear at the top of the program, unindented, before every other statement. V11 explicitly states: "a binding is indented, or follows a statement that is not a binding".

## Snippet B
**Verdict:** INVALID

**Broken rules:** V11

**Explanation:** The binding `a1:ADR = t1.adr` on line 1 references `t1` through a relation, but `t1` is not bound until line 2. Bindings are resolved top to bottom, and a relation binding requires the source name to be bound on an earlier line. V11 states: "its relation starts from a name not bound on an earlier line".

## Snippet C
**Verdict:** VALID

**Explanation:** The binding `t1:Task = TASK-0102` is syntactically correct and unindented at the top. The TRANSITION statement is well-formed and uses a bound name (`t1`). Although the transition will fail at execution time (TASK-0102 is in `Todo` status and no transition to `Done` exists from that state), this is a runtime failure, not a validity error. The DSL specification clarifies: "A transition that the Definition does not permit...is not INVALID: the program is well-formed, and the transition fails when it is executed."
