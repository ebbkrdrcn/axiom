### Trace Explanation

**Line 1–2**: The first `HITL` awaits a response. The human provides "Approved. The security review is done too, so skip the security question and release right away." According to DSL rule 8 (Outcomes), only the chosen answer counts; the commentary is additional and affects nothing. The answer `approved` establishes outcome `release.approved`.

**Line 3**: The first `WHEN release.approved` evaluates to true and its flow runs.

**Line 4**: The nested `HITL:security` is reached and execution waits for a response.

**Line 5**: The event states "Nobody answers the security question; the runtime stops waiting." This makes the response unavailable. Per DSL rule 12, when an operation fails and has a `FALLBACK`, the fallback runs. The `HITL` has a `FALLBACK`, so it executes instead of continuing normally.

**Line 6–7**: The fallback flow executes: `TRANSITION "Blocked"` sets the process state, then `STOP` ends execution immediately. The `WHEN security.passed` and `WHEN release.rejected` are never reached because execution has ended.
