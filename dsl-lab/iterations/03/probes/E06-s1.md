# E06 — Execution of the program against the fixtures

## Program

```text
t1:Task = TASK-0102
TRANSITION t1 "Review"
  → FALLBACK
      → TRANSITION "Blocked"
      → STOP
EMIT status-report
```

## 1. Validity verdict

**VALID**

Check against V1–V12:

- V1 — indentation is well-formed: the binding is unindented and at the top; `→ FALLBACK` and its two children are indented consistently with the grammar (`fallback = INDENT, "→", "FALLBACK", NL, INDENT, flow, DEDENT, DEDENT`). No line fails to match a statement form.
- V2/V3 — the only `BREAK`-related construct is absent here (the fallback ends in `STOP`, not `BREAK`); not applicable.
- V4 — the `→ FALLBACK` is written directly under `TRANSITION t1 "Review"` (an entity `TRANSITION`), which is one of the permitted parents (`HITL`, `REQUIRE`, `VERIFY`, `TRANSITION <name>`), and there is exactly one `FALLBACK` for it.
- V5 — no `AUTO` in the program.
- V6 — no `WHEN` in the program, so nothing to check.
- V7 — no `HITL` in the program.
- V8 — the last item of the fallback flow is `STOP`. Satisfied.
- V9 — no `FORK`/`JOIN` in the program.
- V11 — the only binding (`t1:Task = TASK-0102`) is at the top, unindented, before any other statement, and binds `t1` only once.
- V12 — `TRANSITION t1 "Review"` uses `t1`, which is bound; `t1` is not used as a `HITL` name.

No rule is broken → **VALID**.

## 2. Execution trace

Fixture used for binding: `docs/tasks/TASK-0102.md`

```
id: TASK-0102
type: Task
status: Todo
```

Task Definition transition table (`docs/types/task/definition.md`):

| From | To | Precondition |
|---|---|---|
| Todo | InProgress | none |
| InProgress | Review | verified: accepted |
| InProgress | Debugging | verified: rejected |
| Debugging | InProgress | none |
| Review | InProgress | none |
| Review | Done | human: approved |

There is no declared change `Todo → Review`, so `TRANSITION t1 "Review"` fails (condition 3 of the entity-`TRANSITION` rule: "the change from the current status to `<status>` is declared by the Definition").

```trace
0. validate -> VALID
1. t1:Task = TASK-0102 -> bound TASK-0102
2. TRANSITION t1 "Review" -> failed: Todo → Review is not a transition declared by the Task Definition; fallback
3. TRANSITION "Blocked" -> state = "Blocked"
4. STOP -> stop
```

`EMIT status-report` is never reached: the fallback flow runs *instead of* the normal flow, and it ends in `STOP`, which ends the whole execution immediately (no further statement runs anywhere).
