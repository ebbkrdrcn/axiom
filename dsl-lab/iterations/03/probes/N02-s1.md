# Execution of the review program — five runs

Program:

```text
HITL:review[approved, rejected]("Approve the design document?")
  → FALLBACK
      → TRANSITION "Pending"
      → STOP
WHEN review.approved
  → TRANSITION "Approved"
WHEN review.rejected
  → TRANSITION "Rework"
```

Validation: the program is VALID (a single decision `HITL` with a matching `FALLBACK` ending in `STOP`, and two `WHEN`s each testing a listed answer of `review`; no rule V1–V12 is broken).

For each run, execution reaches `HITL:review[...]` and waits for a response to that question. The response is classified per the DSL's usable/insufficient/unavailable rules, then the corresponding statements run.

## Run A — "Approved, but fix the typo in section 2 later."

- **Classification:** usable — the response clearly selects the listed answer `approved`; the added remark about the typo is extra and changes nothing else.
- **Outcome:** `review.approved` is established.
- **Flow:** execution continues after the `HITL` (the `FALLBACK` does not run). `WHEN review.approved` is true → `TRANSITION "Approved"`. `WHEN review.rejected` is false (the latest outcome of `review` is `approved`, not `rejected`) → skipped.
- **Final process state:** `Approved`.

## Run B — "Not like this, the API section is wrong."

- **Classification:** usable — the response clearly refuses (equivalent to the specification's own example, "Not like this, rewrite the intro." → usable: rejected); naming what is wrong is extra and does not change the answer.
- **Outcome:** `review.rejected` is established.
- **Flow:** execution continues after the `HITL`. `WHEN review.approved` is false → skipped. `WHEN review.rejected` is true → `TRANSITION "Rework"`.
- **Final process state:** `Rework`.

## Run C — "Looks good to me, ship it!"

- **Classification:** usable — the response clearly and unambiguously means `approved`.
- **Outcome:** `review.approved` is established.
- **Flow:** execution continues after the `HITL`. `WHEN review.approved` is true → `TRANSITION "Approved"`. `WHEN review.rejected` is false → skipped.
- **Final process state:** `Approved`.

## Run D — "Maybe, I need to check with legal first."

- **Classification:** insufficient — the decision is deferred/not yet made (no listed answer is selected), comparable to the specification's own example "Let me think about it next week." → insufficient.
- **Outcome:** none is established (a failed/insufficient `HITL` establishes no outcome).
- **Flow:** because the `HITL` has a `FALLBACK`, the fallback flow runs instead of the normal flow: `TRANSITION "Pending"`, then `STOP`. Execution ends there; the two `WHEN` statements are never reached (and would be false regardless, since `review` holds no outcome).
- **Final process state:** `Pending`.

## Run E — "Yes and no."

- **Classification:** insufficient — ambiguous between both listed answers, comparable to the specification's own example "Approve and reject both." → insufficient.
- **Outcome:** none is established.
- **Flow:** the `FALLBACK` runs: `TRANSITION "Pending"`, then `STOP`. Execution ends; the `WHEN` statements are not reached.
- **Final process state:** `Pending`.
