# Validation Results for DSL Snippets

## Snippet A
```
LOOP:deploy
  DELEGATE deploy
  VERIFY deploy
  WHEN deploy.accepted
    → BREAK release
```

**INVALID**

**Rules broken:**
- **V1**: The form `BREAK release` is invalid. According to the syntax rules, `BREAK` is a keyword that stands alone with no arguments. The grammar specifies `BREAK` as a simple statement: `( "JOIN" | "BREAK" | "WAIT" | "STOP" ) , NL`. The line "→ BREAK release" does not match any valid statement form.

## Snippet B
```
FORK
  → LOOP:retry
      DELEGATE upload
      VERIFY upload
      WHEN upload.accepted
        → BREAK
  → DELEGATE docs
JOIN
```

**VALID**

No rules are broken. This is a well-formed program:
- The FORK has two branches (required minimum met)
- The first branch contains a LOOP with a BREAK inside it; the BREAK leaves only the innermost LOOP (which is inside the branch), satisfying rule V3
- The second branch contains a single DELEGATE statement
- The JOIN waits for both branches to complete before continuing
- All indentation and scoping rules are satisfied

## Snippet C
```
FORK
  → VERIFY api
  → VERIFY ui
WHEN api.accepted
  → EMIT api-report
```

**INVALID**

**Rules broken:**
- **V10**: The `WHEN api.accepted` tests an outcome (`api.accepted`) that is established by a branch of the `FORK` in the same flow (the first branch runs `VERIFY api`), but there is no `JOIN` of that `FORK` written between the `FORK` and the `WHEN`. According to rule V10, this makes the branch outcome untestable in that flow. A `JOIN` must be inserted between the FORK and the WHEN for the program to be valid.

## Snippet D
```
HITL:release[approved, rejected]("Release now?")
WHEN release.approved
  → EMIT release
```

**VALID**

No rules are broken. This is a well-formed program:
- The HITL is a valid decision with name `release` and answer list `[approved, rejected]`
- The HITL has no fallback (which is optional per the grammar `[ fallback ]`)
- The WHEN statement is at the same indentation level as the HITL, making it a separate statement that follows
- The WHEN condition tests one of the valid outcomes established by the HITL
- All syntax and scoping rules are satisfied

## Snippet E
```
t1:Task = TASK-0100
VERIFY t1
WHEN t1.accepted
  → TRANSITION t2 "Review"
```

**INVALID**

**Rules broken:**
- **V12**: The `TRANSITION t2 "Review"` references the name `t2`, which is not bound. Only `t1` is bound at the top of the program by the statement `t1:Task = TASK-0100`. Rule V12 states that "`TRANSITION <name> "<status>"` uses a name that is not bound". A binding for `t2` would be required at the top level before this transition can be used.
