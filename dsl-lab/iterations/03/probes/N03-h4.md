## Execution Explanation

1. The first HITL:release is reached and waits for a response.
2. The human provides "Approved. The security review is done too, so skip the security question and release right away." This is a usable response that establishes outcome `release.approved`. The additional text (about skipping the security question) is commentary and does not change execution per DSL rule: "Only the chosen answer counts. Anything else in a response...adds no statement."
3. WHEN release.approved is checked (true). The flow under it runs, which contains HITL:security.
4. HITL:security is reached and the execution waits for a response.
5. According to the event, "Nobody answers the security question; the runtime stops waiting." The response is unavailable. Since HITL:security has a FALLBACK defined, the fallback flow executes.
6. The fallback flow executes TRANSITION "Blocked", setting the process state to "Blocked".
7. STOP is executed, ending the entire program immediately.

The remaining WHEN statements (security.passed and release.rejected) are never reached because execution stopped.
