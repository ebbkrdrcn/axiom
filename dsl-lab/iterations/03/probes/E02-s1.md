# Execution of the E02 program

```text
t1:Task = ADR-0100
TRANSITION "Started"
DELEGATE work
```

## 1. Validity verdict

**VALID**

The binding `t1:Task = ADR-0100` is syntactically a well-formed binding (`<name>:<Type> = <identity>`), written unindented as the first statement, referring to a name (`t1`) that is not bound anywhere else and not used as a `HITL` name. No rule V1–V12 is broken:

- V11 is not broken: the binding is unindented, is the first statement, and `t1` is bound only once.
- V12 is not broken: `t1` is not used as a `HITL` name.
- No other line introduces indentation, `→` items, `AUTO`, `FORK`/`JOIN`, `BREAK`, or `WHEN` conditions, so V1–V10 do not apply.

That `ADR-0100` is actually of type `ADR`, not `Task`, is **not** a validity problem. Per `dsl.md` (Entities → Binding) and `entity-model.md` ("Type mismatch" example), a type mismatch on a binding is an **execution failure**, not an INVALID program: "The program is well-formed, but the binding is not satisfied, so execution ends before any other statement."

## 2. Execution trace

Bindings are resolved once, first, top to bottom (Execution rule 11), before any other statement runs. Resolving `t1:Task = ADR-0100`:

- The interpreter locates the representation whose declared `id` equals `ADR-0100`: `docs/adr/ADR-0100.md`. Exactly one representation declares that identity.
- Its declared `type` is `ADR`, not `Task`.
- Because the entity is not of the declared type `Task`, the binding is **not satisfied**.

Per the binding rule ("Anything else → Execution ends, as with `STOP`. No statement after the bindings runs."), execution ends immediately. `TRANSITION "Started"` and `DELEGATE work` are never reached.

```trace
0. validate -> VALID
1. t1:Task = ADR-0100 -> failed: binding not satisfied (ADR-0100 is type ADR, not Task); stop
```

No further lines are produced: execution does not end normally (rule 10 does not apply), so there is no `(end of program) -> end` line — the failed binding itself is the terminating step, traced with `; stop` as its final effect.

- **No entity files changed.** `TRANSITION "Started"` (a process-state transition, not an entity transition) and `DELEGATE work` never executed, and the failed binding itself performs no write (reading and failing to match a type modifies nothing). Specifically:

Per `dsl.md`, "Before the first `TRANSITION`, the process state is `none`," and no `TRANSITION` ever runs in this execution.
