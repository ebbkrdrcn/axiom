# E12 Validation Results

## Snippet A
**INVALID**

Breaks rule **V11**: A binding is indented (inside a LOOP scope). Bindings must appear at the top of the program, unindented, before every other statement.

The line `a1:ADR = t1.adr` is indented within the LOOP body, which violates the requirement that bindings appear only at the top level.

## Snippet B
**INVALID**

Breaks rule **V11**: The binding's relation starts from a name not bound on an earlier line.

The first line `a1:ADR = t1.adr` attempts to bind `a1` to the relation `adr` of `t1`, but `t1` is not bound until the next line. Bindings must reference only names that are bound on earlier lines.

## Snippet C
**VALID**

This program is well-formed. All validity rules V1-V12 are satisfied:
- The binding `t1:Task = TASK-0102` is at the top level, unindented, and refers to an entity that exists
- TASK-0102 exists, is of type Task, and is structurally valid
- The TRANSITION statement uses the bound name `t1`

The fact that the transition from Todo to Done is not declared in the Task Definition means the TRANSITION will fail at execution time, but the program itself is not INVALID. As stated in the DSL specification: "A transition that the Definition does not permit... is not INVALID: the program is well-formed, and the transition fails when it is executed."
