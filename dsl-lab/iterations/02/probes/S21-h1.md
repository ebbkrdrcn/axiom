# Execution Trace and Analysis

## Step-by-step Execution

1. `TRANSITION "Testing"` → state = "Testing"
2. `WHEN tests.accepted` → false: skip
3. `DELEGATE tests` → done
4. `VERIFY tests` → outcome tests.accepted
5. `EMIT test-report` → done
6. (end of program) → end

## Final State

**"Testing"**

## Is `TRANSITION "Review"` ever executed?

**No.**

## Explanation

The `TRANSITION "Review"` statement is never executed because the `WHEN tests.accepted` condition is evaluated before the `tests.accepted` outcome has been established.

Key points from the specification:

- A `WHEN` is checked once when execution reaches it (Execution rule 2)
- Before anything establishes an outcome, every `WHEN` on it is false (Outcomes section: "Not yet established")
- `WHEN` constructs are not standing triggers and are never re-checked (Outcomes section: "The outcome is established later. Nothing happens. A `WHEN` is not a standing trigger and is never re-checked.")

At the point where the `WHEN tests.accepted` statement is reached, the `VERIFY tests` statement that would establish `tests.accepted` has not yet executed. Therefore, the condition is false, the flow is skipped, and `TRANSITION "Review"` never runs. Later, when `VERIFY tests` establishes `tests.accepted`, the `WHEN` is not re-evaluated.
