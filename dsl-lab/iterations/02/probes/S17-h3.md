# Solution: go_harness DSL for Test Delegation and Diagnosis

## DSL Program

```
DELEGATE tests
VERIFY tests
WHEN tests.accepted
  → TRANSITION "Review"
WHEN tests.rejected
  → TRANSITION "Debugging"
  → DELEGATE diagnosis
```

## Assumptions Made

1. **Work name for test suite**: I assumed the delegated work should be named `tests`. The specification requires an identifier but does not prescribe the name. The requirement says "the test suite" without specifying how to refer to it in the DSL.

2. **Work name for diagnosis**: I assumed the diagnostic work should be named `diagnosis`. The requirement says "delegate a diagnosis" but does not specify the identifier for this work.

3. **No outer loop or control structure**: I assumed the flow should be linear and not wrapped in a `LOOP`. The requirement describes a single sequence of steps without indicating repetition.

4. **No prerequisite requirements**: I assumed no `REQUIRE` statement is needed. The requirement does not mention any resources or conditions that must be available before the test suite can be delegated.

5. **Execution continues after diagnosis**: I assumed the program does not end after delegating the diagnosis. The specification states that execution ends naturally after the last top-level statement unless `STOP` is used. The requirement does not ask for the program to end, so execution would continue if there were further statements.

6. **Outcomes from VERIFY**: I assumed that `VERIFY tests` produces exactly two possible outcomes: `tests.accepted` (tests pass) and `tests.rejected` (tests fail), as specified in the DSL for the `VERIFY` statement.
