# go_harness DSL for Release Workflow

```
REQUIRE repository
  → FALLBACK
      → TRANSITION "Blocked"
      → STOP
LOOP:delivery
  FORK
    → DELEGATE implementation
    → DELEGATE documentation
  JOIN
  VERIFY implementation
  WHEN implementation.accepted
    → BREAK
  WHEN implementation.rejected
    → DELEGATE correction
AUTO HITL:release[now, later]("Release now or later?")
  → FALLBACK
      → TRANSITION "Waiting"
      → STOP
WHEN release.now
  → EMIT release
  → TRANSITION "Released"
WHEN release.later
  → TRANSITION "Scheduled"
```

## Assumptions

1. **Loop structure**: The "repeatedly" phase is implemented as `LOOP:delivery` with a `BREAK` statement triggered when implementation is accepted. The loop repeats by reaching the body start again when implementation is rejected.

2. **Concurrent execution**: "at the same time, delegate the implementation and documentation" is implemented using `FORK` with two branches and `JOIN` to synchronize before verification.

3. **Correction iteration**: When implementation is rejected, "delegate a correction and repeat" means the `DELEGATE correction` statement runs, and control returns to the loop start (implicitly via the end of loop body).

4. **Agent decision authority**: The `AUTO HITL:release[now, later]` assumes the agent may resolve this decision when sufficiently determined (e.g., from code quality, test results), and asks the human otherwise.

5. **Answer mapping**: The decision options "release now or later" map to the answer list `[now, later]` in the HITL construct.

6. **Release emission scope**: `EMIT release` and `TRANSITION "Released"` both execute when the human/agent chooses "now", sequenced in the `WHEN release.now` flow.

7. **Fallback trigger**: "If no usable answer is obtained" means an insufficient or unavailable response from the human to the HITL, triggering the fallback flow.

8. **Final state if later**: Choosing "later" only transitions to "Scheduled"; no explicit emission or further action is specified, so the program ends normally.

9. **Repository identifier**: "repository" is treated as a simple identifier naming the required context/state, per the DSL's abstract semantics (the actual retrieval mechanism is unspecified).

10. **Correction outcome**: The `DELEGATE correction` statement establishes no outcome; its success or failure is determined by the next `VERIFY implementation` in the following loop iteration.
