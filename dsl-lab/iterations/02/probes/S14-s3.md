## 3. Assumption (not determined by the specification)

The specification states that `FORK` branches run concurrently and that statements *within* a branch run sequentially (rule 1, rule 4, and the `FORK` section), but it does not define a precise interleaving model for statements *across* different branches — only that `JOIN` waits until all branches are complete regardless of order. Since the task states the integration-tests branch "finishes later," I assume the unit-tests branch's `DELEGATE`/`VERIFY` pair completes in full before the integration-tests branch's `DELEGATE`/`VERIFY` pair completes, and I list branch steps in that completion order. This ordering choice does not affect the outcome: `JOIN` only requires that both branches be complete, and outcomes are visible after `JOIN` regardless of which branch produced them first.
