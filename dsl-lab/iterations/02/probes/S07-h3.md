# Analysis of go_harness DSL Program

## Program
```
DELEGATE data-migration
WAIT
VERIFY data-migration
WHEN data-migration.accepted
  → TRANSITION "Migrated"
```

## Answers

### 1. What does `WAIT` wait for here?

The specification explicitly states: "The DSL does not name the event. The surrounding process and the runtime determine it." Therefore, the specification does not prescribe what event WAIT is waiting for. The nature of the event is determined by the surrounding process context and the runtime environment, not by the DSL syntax itself.

In practical terms, given that WAIT follows a DELEGATE statement, it is reasonable to infer the runtime would likely wait for the delegated work to complete and return a result, but this is not defined by the DSL specification.

### 2. What executes immediately after `WAIT` ends?

The next statement in the program is `VERIFY data-migration`. According to the specification: "After the event, the next statement runs." Therefore, execution continues with the `VERIFY` statement.

### 3. Does reaching `VERIFY data-migration` imply that the migration succeeded?

No. The specification clarifies: "The completion of delegated work is not a successful verification." The `VERIFY` statement evaluates a result against acceptance criteria and establishes exactly one outcome: either `<result>.accepted` or `<result>.rejected`. Reaching the `VERIFY` statement does not guarantee a positive outcome—it merely performs the evaluation. The result could be accepted or rejected based on the applicable criteria.

### 4. What happens if the awaited event never occurs?

Execution remains suspended at the `WAIT`. The specification states: "There is no timeout. If the event never comes, execution stays at the `WAIT`." The execution will not proceed to the next statement and will not advance further in the program.
