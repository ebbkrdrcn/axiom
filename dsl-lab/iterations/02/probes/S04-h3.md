# go_harness DSL for Deployment Process

## DSL Program

```
REQUIRE deployment-target
HITL:region[eu, us]("Which region to deploy to: eu or us?")
  → FALLBACK
      → TRANSITION "Blocked"
      → STOP
WHEN region.eu
  → DELEGATE eu-deployment
WHEN region.us
  → DELEGATE us-deployment
EMIT deployment-log
```

## Assumptions Made

1. **HITL outcome name and answers**: The requirement does not prescribe the exact name for the human decision. I chose "region" as a descriptive identifier for the outcome, with answer options "eu" and "us" matching the requirement exactly.

2. **Delegated work names**: The requirement specifies to "delegate eu-deployment; if us, delegate us-deployment" but does not prescribe the exact identifiers used. I used "eu-deployment" and "us-deployment" as descriptive names for the work items.

3. **Emitted artifact name**: The requirement says "emit a deployment-log". I interpreted this as `EMIT deployment-log`, using "deployment-log" as the artifact identifier.

4. **REQUIRE item name**: The requirement says "the process needs the deployment-target". I used "deployment-target" as the required item identifier.

5. **FALLBACK behavior**: I interpreted "If no usable answer is obtained" to map to the DSL concept of an insufficient or unavailable HITL response, which triggers the FALLBACK flow according to the specification.

6. **WHEN structure**: I used two consecutive, independent WHEN statements (WHEN region.eu and WHEN region.us) because the specification states "Consecutive WHENs are independent. Every one that is true runs, top to bottom." Exactly one of these will be true based on the human's choice.

7. **Final EMIT placement**: The requirement says "Finally emit a deployment-log". I placed EMIT deployment-log outside and after all conditional logic, so it executes after the appropriate delegation completes, regardless of which region was chosen.

8. **Termination with STOP**: The fallback flow's last statement must be `STOP` or `BREAK` per the specification (rule V8). Since the requirement says to "terminate the whole execution" and we are not inside a loop, `STOP` is the correct terminator.

## Validity Verification

The program satisfies all validity rules V1–V10:
- V1: Indentation is well-formed (FALLBACK under HITL, flow items properly nested)
- V2: No BREAK outside a LOOP
- V3: No BREAK in a FORK branch
- V4: `→ FALLBACK` is directly under the HITL construct
- V5: No AUTO usage
- V6: WHEN conditions reference outcomes ("eu" and "us") declared in the HITL answer list
- V7: No duplicate HITL names; answer list is non-empty with no duplicates
- V8: Fallback flow ends with STOP
- V9: No FORK or JOIN present
- V10: No branch outcome visibility issues
