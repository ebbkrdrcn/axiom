# Execution Trace: Two Iterations of LOOP:build

## First Iteration

1. `LOOP:build` is entered
2. `DELEGATE build` → The actor performs the work and delivers a result (done)
3. `VERIFY build` → The result is evaluated. Since `VERIFY build` establishes `build.rejected` in every iteration, the outcome `build.rejected` is now established
4. `WHEN build.accepted` → The condition is checked. The current outcome of `build` is `rejected`, not `accepted`. The condition is **false**, so the flow (containing `BREAK`) is skipped
5. The last statement of the loop body is complete. Execution continues with the next statement in the loop body, which is the first statement again

## Second Iteration

1. `DELEGATE build` → The actor performs the work and delivers a result (done)
2. `VERIFY build` → The result is evaluated. The outcome is replaced by `build.rejected` (the most recent value for the subject `build`)
3. `WHEN build.accepted` → The condition is checked. The current outcome of `build` is still `rejected`, not `accepted`. The condition is **false**, so the flow is skipped
4. The last statement of the loop body is complete. Execution continues with the next statement in the loop body, which is the first statement again

## Execution of EMIT build-report

**`EMIT build-report` is never executed.**

The loop continues indefinitely because:
- Each iteration establishes `build.rejected`
- The `WHEN build.accepted` condition is always false
- `BREAK` is never executed (it is inside the skipped flow)
- Without `BREAK` or `STOP`, the loop has no exit condition

Execution remains trapped in the loop, repeatedly delegating, verifying (always getting `rejected`), checking the false condition, and looping again. `EMIT build-report` can only run after the loop exits, which never occurs.
