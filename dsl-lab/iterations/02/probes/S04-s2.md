```text
REQUIRE deployment-target
HITL:region[eu, us]("Which region would you like to deploy to?")
  → FALLBACK
      → TRANSITION "Blocked"
      → STOP
WHEN region.eu
  → DELEGATE eu-deployment
WHEN region.us
  → DELEGATE us-deployment
EMIT deployment-log
```

## Assumptions

The specification does not fully determine every detail of the requirement's wording, so the following choices were made:

1. **HITL subject name.** The requirement says "ask a human which region to deploy to: eu or us" but never gives a name for this decision. I introduced the identifier `region` as the `HITL` name (`HITL:region[...]`), since the grammar requires a name for a decision-form `HITL` and none was supplied.

2. **Exact question text.** The requirement does not quote the exact wording to ask the human. I used `"Which region would you like to deploy to?"` as a reasonable rendering of "ask a human which region to deploy to."

3. **No `FALLBACK` on `REQUIRE deployment-target`.** The requirement only says the process "needs the deployment-target before anything else" and specifies no behavior for when it cannot be obtained. Per the spec, a bare `REQUIRE` with no `FALLBACK` simply waits until the item is available, and if the runtime determines it can never be obtained, execution ends as with `STOP` by default. Since the requirement gives no distinct fallback behavior for this case, none was added — only the requirement's own explicit "Blocked/terminate" behavior (for the region decision) was encoded as a `FALLBACK`.

4. **"No usable answer" maps to the `HITL` fallback covering both "insufficient" and "unavailable" responses.** The spec's `HITL` semantics already treat any response that is not a clear, usable selection from `[eu, us]` (i.e., ambiguous, off-topic, or simply never given) as triggering the same `FALLBACK` path. The requirement's phrase "If no usable answer is obtained" was read as exactly this combined case, so a single `FALLBACK` was used rather than distinguishing "wrong answer" from "no answer."

5. **`TRANSITION "Blocked"` then `STOP`, in that order.** The requirement says "transition to state 'Blocked' and terminate the whole execution." Per rule V8, the fallback flow must end with `STOP` or `BREAK`, so `TRANSITION "Blocked"` was placed first and `STOP` last, matching both the requirement's stated order and the validity rule.

6. **Identifiers for delegated work and the emitted artifact.** `eu-deployment`, `us-deployment`, and `deployment-log` were used as identifiers directly from the requirement's own terms ("delegate eu-deployment," "delegate us-deployment," "emit a deployment-log"), formed as valid identifiers (letters, digits, `-`, `_`, starting with a letter).

7. **No `AUTO`.** The requirement gives no indication that the agent may ever answer the region decision itself, nor any criteria by which it could determine eu vs. us automatically. The `HITL` was therefore left as a plain (non-`AUTO`) decision, always requiring a human answer.

8. **Answer list is exactly `[eu, us]`, exhaustive.** The requirement states the choice is "eu or us," so the `HITL` answer list contains only these two values, and the two `WHEN` branches (`region.eu`, `region.us`) cover them in the same order as stated in the requirement.

9. **`EMIT deployment-log` is unconditional in the surviving (non-fallback) path.** "Finally emit a deployment-log" was read as the last step of the normal flow, running after whichever of the two `DELEGATE` branches executed. It is not reached at all if the fallback path runs, since that path ends in `STOP` before execution would ever get there — consistent with "terminate the whole execution" on the no-usable-answer path.

10. **No `REQUIRE` or `VERIFY` on the deployment work.** The requirement does not ask for verification of `eu-deployment`/`us-deployment`, so none was added; only `DELEGATE` is used for those steps, per "delegate eu-deployment" / "delegate us-deployment" as literally stated.
