## Broken Rule

**Rule V3:** `BREAK` is inside a `FORK` branch, and the `LOOP` it would leave is outside that branch.

## Detailed Explanation

The program structure is:

```
LOOP:review
  FORK
    → DELEGATE security-review
        VERIFY security-review
        WHEN security-review.rejected
          → BREAK
    → DELEGATE docs-review
        VERIFY docs-review
  JOIN
  TRANSITION "Reviewed"
EMIT review-summary
```

The problematic `BREAK` statement is located inside the first branch of the `FORK`:
- The branch is: `→ DELEGATE security-review` with nested statements
- The `BREAK` is nested under the `WHEN security-review.rejected` flow
- This `BREAK` is inside a `FORK` branch

The `LOOP` that this `BREAK` would exit is `LOOP:review`. However, `LOOP:review` is outside the branch—it is the parent statement that contains the `FORK`. According to rule V3, a `BREAK` inside a `FORK` branch is only valid if the `LOOP` it leaves is also inside that same branch. Since `LOOP:review` is outside the branch, the rule is violated.
