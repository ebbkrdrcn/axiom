# Answers

## Snippet 1

```
AUTO HITL:deploy[yes, no]("Deploy to production?")
WHEN deploy.yes
  → EMIT deployment
```

**VALID.**

- `AUTO` is written directly before `HITL:deploy[...]`, on the same line, and that `HITL` is a decision form (has a name `deploy` and an answer list `[yes, no]`) — this satisfies the requirement of rule **V5** ("`AUTO` is not immediately followed, on the same line, by a decision `HITL:<name>[…]`" — here it is, so V5 is not broken).
- `WHEN deploy.yes` tests `deploy.yes`; `yes` is one of the listed answers of `HITL:deploy[yes, no]`, so the subject/outcome pair is one the program can produce — rule **V6** is satisfied.
- The `→ EMIT deployment` item is a `→` item directly under a `WHEN`, which is permitted (per the Indentation/Arrow rules and V4).
- No `FALLBACK`, `BREAK`, `FORK`/`JOIN`, or duplicate-name issues are present, so V2, V3, V4 (other clauses), V7, V8, V9, V10 are not implicated.

No rule is violated: the program is well-formed.

## Snippet 2

```
AUTO DELEGATE implementation
VERIFY implementation
```

**INVALID — rule V5.**

Rule V5: "`AUTO` is not immediately followed, on the same line, by a decision `HITL:<name>[…]`." Here `AUTO` is followed on the same line by `DELEGATE implementation`, not by a decision `HITL`. The spec also explicitly lists this exact construct as an invalid example:

```invalid
AUTO DELEGATE implementation
```

So this snippet is INVALID under V5.

## Snippet 3

```
HITL:deploy[yes, no]("Deploy to production?") AUTO
WHEN deploy.yes
  → EMIT deployment
```

**INVALID — rule V5.**

The specification states: "`AUTO` is written directly before `HITL`, on the same line" (section **AUTO**), and the grammar confirms this ordering: `hitl = ( [ "AUTO" ] , "HITL:" , identifier , ... )` — `AUTO` is an optional token that must precede `"HITL:"`.

In this snippet, `AUTO` appears *after* the closing `)` of the `HITL` construct, not immediately before `HITL:deploy[...]`. Therefore `AUTO` is not "immediately followed, on the same line, by a decision `HITL:<name>[…]”` (it instead follows the whole `HITL` statement), which breaks rule **V5**. It also does not conform to the grammar's `hitl` production, which is the syntactic expression of the same requirement.

## Snippet 4

```
AUTO
HITL:deploy[yes, no]("Deploy to production?")
```

**INVALID — rule V5.**

Rule V5 requires `AUTO` to be immediately followed, **on the same line**, by a decision `HITL:<name>[…]`. Here `AUTO` is on its own line, separate from the `HITL:deploy[...]` statement on the next line, so the "same line" requirement is not met. This also does not match the grammar's `hitl` production (`[ "AUTO" ] , "HITL:" , ...` must be one statement/line) and is analogous to the spec's own invalid example where `AUTO` stands alone followed by other lines:

```invalid
AUTO
  WHEN decision.uncertain
    → HITL("Approve?")
```

So this snippet is INVALID under V5.

---

## Assumption noted

The specification does not give an explicit example of `AUTO` placed *after* `HITL` (Snippet 3) as either valid or invalid; I inferred its invalidity from (a) the prose statement that `AUTO` is written "directly before `HITL`, on the same line," and (b) the grammar rule `hitl = ( [ "AUTO" ] , "HITL:" , ... )`, which fixes `AUTO` as a token preceding `HITL:` in the same production. Both point to the same rule, V5, being the applicable one, since V5 is the rule governing `AUTO`'s required adjacency/position relative to a decision `HITL`.
