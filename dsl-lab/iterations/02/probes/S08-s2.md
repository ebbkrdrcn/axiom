# Answer

The program:

```
REQUIRE staging-credentials
DELEGATE deployment
EMIT deployment-log
```

has no `→ FALLBACK` attached to the `REQUIRE` (the grammar for `require` is `"REQUIRE" , identifier , NL , [ fallback ]`, and here nothing follows `REQUIRE staging-credentials` at an indented, `→ FALLBACK`-shaped child). The program is otherwise well-formed under Validity rules V1–V10 (no `LOOP`, `BREAK`, `FORK`/`JOIN`, `WHEN`, `HITL`, or `AUTO` appear, so those rules are vacuously satisfied), so it is valid and executable.

## 1. What happens at `REQUIRE staging-credentials`?

Per the `REQUIRE` rules:

| Situation | What happens |
|---|---|
| The runtime determines the item cannot be obtained, and there is a `FALLBACK` | Run the fallback flow. |
| The runtime determines the item cannot be obtained, and there is no `FALLBACK` | Execution ends, as with `STOP`. |

Here the runtime has determined that `staging-credentials` cannot be obtained (this is stronger than "not yet available," which would just make execution wait at the `REQUIRE`). Since this `REQUIRE` has no attached `→ FALLBACK`, the applicable row is the second one: **execution ends, as with `STOP`.** `REQUIRE` establishes no outcome, so nothing is recorded for `staging-credentials` beyond the fact that execution has ended.

In trace-effect terms, this step would be written as:

```trace
1. REQUIRE staging-credentials -> stop
```

(using the `stop` effect, since the specification says this case behaves "as with `STOP`"; no other listed effect fits an item that is determined unobtainable with no fallback).

## 2. Is `DELEGATE deployment` executed?

No. Execution rule 5 ("Stop at a boundary") and the `REQUIRE` table both say that when the required item cannot be obtained and there is no `FALLBACK`, execution ends — it does not continue to the next statement. `DELEGATE deployment` is the statement immediately after the `REQUIRE`, and it is never reached. Per the execution procedure, the agent must "never skip, reorder, merge, or add statements," but ending execution at the `REQUIRE` is not skipping a statement — it is the defined outcome of an unsatisfiable `REQUIRE` with no fallback; the remainder of the program simply is not run.

## 3. Is `EMIT deployment-log` executed?

No, for the same reason: execution already ended at the `REQUIRE`, before reaching `DELEGATE deployment`, so `EMIT deployment-log`, which comes later still, is not executed either.
