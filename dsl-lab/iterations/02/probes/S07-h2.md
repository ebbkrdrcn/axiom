# Answers to go_harness DSL Task

## 1. What does `WAIT` wait for here?

The specification does not determine a specific event name. According to the WAIT section: "The DSL does not name the event. The surrounding process and the runtime determine it."

In this program, `WAIT` follows `DELEGATE data-migration`. The runtime (not the DSL) determines what event to wait for. In practical terms, given the context, execution would wait for the delegated actor to deliver its result from the data-migration work. However, the DSL itself is intentionally abstract about this.

## 2. What executes immediately after `WAIT` ends?

`VERIFY data-migration` executes immediately after `WAIT` ends.

According to the WAIT specification: "After the event, the next statement runs." The next statement in the program after `WAIT` is `VERIFY data-migration`.

## 3. Does reaching `VERIFY data-migration` imply that the migration succeeded?

No. Reaching `VERIFY data-migration` does **not** imply the migration succeeded.

According to the VERIFY section: "The completion of delegated work is not a successful verification." Reaching the `VERIFY` statement means we are now evaluating the result against acceptance criteria. The `VERIFY` statement will establish either `data-migration.accepted` or `data-migration.rejected`, but reaching the statement itself tells us nothing about which outcome will be established. Only after `VERIFY` executes do we learn the outcome.

## 4. What happens if the awaited event never occurs?

Execution stays at the `WAIT` statement indefinitely.

According to the WAIT specification: "There is no timeout. If the event never comes, execution stays at the `WAIT`." The program cannot proceed to `VERIFY data-migration` unless the event is delivered. If the event never arrives, the program remains suspended at `WAIT` with no mechanism to time out or recover.
