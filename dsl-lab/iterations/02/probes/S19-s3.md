# Execution of the given go_harness program

## Step 1 — Validate first

Per **Executing a program**, rule 1: *"Validate first. Check rules V1–V10. If any is broken, do not execute."* So before tracing anything, the program must be checked against V1–V10.

The program:

```
HITL:region[eu, us]("Which region should we deploy to?")
  → FALLBACK
      → TRANSITION "Deferred"
      → EMIT deferral-notice
TRANSITION "Deploying"
DELEGATE deployment
```

Checking each rule:

- **V1** (indentation) — The nesting shown (HITL → indented `→ FALLBACK` → further-indented `→` items) matches the required shape from **Indentation and scope** and the `fallback` grammar rule (`INDENT , "→" , "FALLBACK" , NL , INDENT , flow , DEDENT , DEDENT`). Nothing in the text suggests inconsistent spacing, so this is assumed to be well-formed. *(Assumption: the indentation as printed is internally consistent, since the spec judges indentation only by relative depth, not exact column counts, and no conflicting depth is shown.)*
- **V2** (`BREAK` outside a `LOOP`) — no `BREAK` in the program. Not violated.
- **V3** (`BREAK` inside a `FORK` branch leaving a `LOOP` outside that branch) — no `FORK`, no `BREAK`. Not violated.
- **V4** (`→` item misplaced; `→ FALLBACK` not directly under `HITL`/`REQUIRE`; more than one `FALLBACK`) — The single `→ FALLBACK` is directly under the `HITL`, there is only one `FALLBACK`, and the two `→` items inside it (`TRANSITION`, `EMIT`) are under a `FALLBACK`, which is an allowed parent for `→` items. Not violated.
- **V5** (`AUTO` misuse) — no `AUTO` present. Not violated.
- **V6** (`WHEN` testing an undeclared outcome) — there is no `WHEN` statement in the program at all. Not violated.
- **V7** (duplicate `HITL` names, name shared between `HITL`/`VERIFY`, empty/repeated answer list) — only one `HITL` (`region`), no `VERIFY`, and the answer list `[eu, us]` is non-empty with no repeats. Not violated.
- **V8** (*"the last item of a fallback flow is not `STOP` or `BREAK`"*) — The fallback flow attached to `HITL:region` is:
  ```
  → TRANSITION "Deferred"
  → EMIT deferral-notice
  ```
  Its last item is `EMIT deferral-notice`, which is **neither `STOP` nor `BREAK`**. This directly violates **V8**. The spec is explicit and unconditional here: *"Its last item MUST be `STOP` or `BREAK` (rule V8). The fallback never continues into the normal flow."* The worked examples of `FALLBACK` in the spec (e.g. `→ FALLBACK / → TRANSITION "Blocked" / → STOP`) always end the fallback in `STOP` (or `BREAK`); this program's fallback does not.
- **V9** (`JOIN` without a matching `FORK`, or a `FORK` with fewer than two branches) — no `FORK`/`JOIN` present. Not violated.
- **V10** (`WHEN` testing an outcome a still-running `FORK` branch might establish) — no `FORK`, no `WHEN`. Not violated.

**Result: the program is INVALID — it violates V8.**

## Step 2 — Consequence of invalidity

Per the **Validity rules** section: *"A program that breaks any of these rules is INVALID. It MUST be rejected as a whole and MUST NOT be executed in part."*

And per **Executing a program**, rule 1: *"If any is broken, do not execute."*

This means:

- No execution trace can be produced, because execution never begins.
- No statement in the program runs — not the `HITL`, not its `FALLBACK`, and not any statement after it.
- The event given in the task ("the human never responds") is **moot**: it would only matter during execution, and execution is never allowed to start because the program fails validation.

## Answer to the question

**Is `TRANSITION "Deploying"` executed? No.**

Not because of how the `HITL`/`FALLBACK` behaves at runtime, but because the program as a whole is INVALID (it breaks rule V8: the fallback flow under `HITL:region` ends with `EMIT deferral-notice` instead of `STOP` or `BREAK`). An INVALID program "MUST be rejected as a whole and MUST NOT be executed in part," so **nothing in the program executes at all** — including `TRANSITION "Deploying"` and `DELEGATE deployment`, which are never reached regardless of whether the human ever responds to the `HITL`.

## Reported broken rule

- **V8** — the fallback flow attached to `HITL:region[eu, us](...)` ends with `EMIT deferral-notice`, not `STOP` or `BREAK`.
