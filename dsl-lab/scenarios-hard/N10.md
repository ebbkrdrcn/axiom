# N10 — Interpretation: validity of tricky snippets

## Task
For each snippet, answer VALID or INVALID and list every rule it breaks, by number.

Snippet A:
```
LOOP:deploy
  DELEGATE deploy
  VERIFY deploy
  WHEN deploy.accepted
    → BREAK release
```

Snippet B:
```
FORK
  → LOOP:retry
      DELEGATE upload
      VERIFY upload
      WHEN upload.accepted
        → BREAK
  → DELEGATE docs
JOIN
```

Snippet C:
```
FORK
  → VERIFY api
  → VERIFY ui
WHEN api.accepted
  → EMIT api-report
```

Snippet D:
```
HITL:release[approved, rejected]("Release now?")
WHEN release.approved
  → EMIT release
```

Snippet E:
```
t1:Task = TASK-0100
VERIFY t1
WHEN t1.accepted
  → TRANSITION t2 "Review"
```

## Expected
- D1 A INVALID: V1 (`BREAK release` matches no statement form).
- D2 B VALID (the BREAK leaves a LOOP inside the same branch).
- D3 C INVALID: V10 (WHEN tests `api`, established in a branch of a FORK with no JOIN before the WHEN).
- D4 D VALID (a HITL name may equal an EMIT argument).
- D5 E INVALID: V12 (`t2` is not bound).

### Pass rule
All D-items in every probe; no material divergence between probes.
