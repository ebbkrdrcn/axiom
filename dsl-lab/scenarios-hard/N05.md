# N05 — Execution: a request HITL inside a FALLBACK, two runs

## Task
Execute this program twice.

```text
DELEGATE release-candidate
VERIFY release-candidate
HITL:ship[approved, rejected]("Ship the release candidate?")
  → FALLBACK
      → TRANSITION "Blocked"
      → HITL("Tell the release manager that shipping is blocked")
      → STOP
WHEN ship.approved
  → EMIT release
```

Both runs: `VERIFY release-candidate` establishes `accepted`, and the human answers the ship question "Maybe, ask me later."

- Run A: the release manager answers the request: "Noted."
- Run B: nobody answers the request; the runtime stops waiting.

For each run: Answer with: (1) the validity verdict (VALID, or INVALID with every broken rule number); (2) if VALID, the execution trace in the specification's trace format; (3) the final status of every bound entity and which entity files changed, and how (if any entities are bound); (4) the final process state.

## Expected
- D1 Both runs: the ship response is insufficient → the fallback runs; `ship` has no outcome; process state `Blocked`.
- D2 Run A: the request HITL gets a usable response; then STOP.
- D3 Run B: the request HITL is unavailable and has no FALLBACK → execution ends there (as STOP).
- D4 In both runs `EMIT release` does not run; final process state `Blocked`.

### Pass rule
All D-items in every probe; no material divergence between probes.
