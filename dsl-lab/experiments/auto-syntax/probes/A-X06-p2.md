# Answer

## Program under analysis

```text
AUTO HITL:wording("Short or detailed release notes?")
WHEN wording.short
  → DELEGATE short-notes
WHEN wording.detailed
  → DELEGATE detailed-notes
HITL:release("Approve the release?")
WHEN release.approved
  → EMIT release
```

## 1. Which of the two decisions may the agent make by itself, and under what condition?

Only the **wording** decision (`HITL:wording`) may ever be resolved by the agent itself. The **release** decision (`HITL:release`) may not, under any condition.

The reason is purely syntactic and is given directly by the spec: `AUTO` "is written directly before `HITL`, on the same line. It marks that one `HITL` as automatically resolvable." and "`HITL` must not be silently replaced by an agent decision unless that `HITL` is explicitly marked with `AUTO`." In this program, `AUTO` appears only on the line `AUTO HITL:wording(...)`. The line `HITL:release("Approve the release?")` carries no `AUTO` keyword, so per the execution table in the `AUTO` section ("no → The human is asked. The agent must not decide.") the release decision must always go to a human — the agent has no path to decide it itself.

For the wording decision, being marked `AUTO` is necessary but not sufficient. The agent may resolve it itself only under the further condition stated in the `AUTO` section: the decision must be **"sufficiently determined by the available information, criteria, and authority"**, i.e. "the agent can determine a single protocol-compatible decision from the available information and applicable criteria" and has the authority to make it. Concretely here that means the agent can, from the available information and applicable criteria, settle unambiguously on exactly one of `wording.short` or `wording.detailed`. If that condition holds, the agent establishes that outcome directly ("exactly as if a human had given that answer") and the corresponding `WHEN wording.short` / `WHEN wording.detailed` flow runs without anyone being asked. If the condition does not hold (see Q3), the human is asked instead, exactly as for a plain `HITL`.

## 2. All automated checks are green and the agent is highly confident the release should be approved. May it answer "Approve the release?" itself?

No.

This is determined entirely by Q1's answer: `HITL:release("Approve the release?")` is not marked `AUTO` anywhere in the program. Per the spec, absent `AUTO` "the human is asked. The agent must not decide" — this is unconditional and does not depend on how confident the agent is or how strong the supporting evidence (green checks) looks. The spec also explicitly forecloses using confidence as a substitute for the `AUTO` mechanism: "A confidence score alone does not establish certainty," and `AUTO`'s automatic-resolution path only exists for a `HITL` that is syntactically marked `AUTO` in the first place. Since `release` isn't marked, that path is not even available, so the confidence level is moot — the agent must wait for and use the human's actual response to "Approve the release?".

## 3. If the wording decision is not clearly determined, what happens?

`HITL:wording` is marked `AUTO`, but `AUTO` only permits automatic resolution "when the decision is sufficiently determined by the available information, criteria, and authority"; per the spec, uncertainty exists whenever, among other cases, "multiple materially different decisions remain reasonably compatible with the available evidence and criteria" or "the result depends on an unresolved interpretation" — i.e. exactly the situation of the wording decision not being clearly determined. In that case, per the `AUTO` execution table (row "yes / no (uncertain, or outside the agent's authority)"): **"The human is asked, as for a `HITL` without `AUTO`."** The agent does not guess between `short-notes` and `detailed-notes`, and does not skip or default the decision.

Concretely, this means the flow suspends at `HITL:wording` — "The flow containing a `HITL` waits at the `HITL` until either a usable response is available or its `FALLBACK` flow is used" — and the message "Short or detailed release notes?" is put to a human. Once a usable response arrives, it establishes `wording.short` or `wording.detailed` "exactly as if a human had given that answer" would for any `HITL`, and execution continues with the statement after the `HITL` construct, i.e. the two `WHEN wording.short` / `WHEN wording.detailed` constructs are evaluated and the matching one's flow (`DELEGATE short-notes` or `DELEGATE detailed-notes`) runs.

**Gap in the specification that I must flag explicitly:** the program as given attaches **no `FALLBACK`** to `HITL:wording`. The spec says a response that names neither `short` nor `detailed` is "insufficient (see `FALLBACK`)," and that the fallback flow is used "only when the expected response cannot be used to continue the normal flow" (i.e., when the response is unavailable or insufficient). But the spec never states what happens when a `HITL` has *no* `FALLBACK` attached at all and the response turns out to be unavailable or insufficient — `FALLBACK` is presented as an optional attachment, not a mandatory one, and no default behavior is given for its absence. By analogy with `WAIT` ("The DSL defines no timeout... If the event never becomes available, execution remains suspended"), the only textually supported inference is that execution simply remains suspended at `HITL:wording` indefinitely in that scenario, since there is no fallback flow to divert to and no other statement in the spec resolves this case. I am stating this as an explicit assumption/extrapolation, not as something the specification determines: **the specification does not determine what happens when a fallback-less `HITL`'s response turns out to be unavailable or insufficient.**

To summarize part 3: if the wording decision is not clearly determined, the agent must not decide it itself (this is the one required, spec-determined consequence); the decision reverts to a normal `HITL` and a human is asked; if the human gives a usable `short`/`detailed` answer, the corresponding `WHEN` flow executes; what happens if that human response is itself unavailable or insufficient is not determined by the spec for this program, since no `FALLBACK` is attached to `HITL:wording` (my assumption, not derivable from the text, is that execution would simply remain suspended, analogous to `WAIT`'s undefined-timeout behavior).
