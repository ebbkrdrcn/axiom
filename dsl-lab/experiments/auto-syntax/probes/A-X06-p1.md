# Answer

## 1. Which of the two decisions may the agent make by itself, and under what condition?

Only the **`wording`** decision (`AUTO HITL:wording("Short or detailed release notes?")`) may be resolved by the agent itself. The **`release`** decision (`HITL:release("Approve the release?")`) may not, because it is a plain `HITL` with no `AUTO` marker — per the spec, "`HITL` must not be silently replaced by an agent decision unless that `HITL` is explicitly marked with `AUTO`."

The condition under which the agent may resolve `wording` itself: `AUTO` permits automatic resolution "only when the agent can determine a single protocol-compatible decision from the available information and applicable criteria" — i.e. the choice between `wording.short` and `wording.detailed` must be sufficiently determined (unambiguous, non-contradictory information and criteria, and the agent must have the authority to decide). If that condition holds, the agent establishes `wording.short` or `wording.detailed` itself, exactly as if a human had answered, and no human is asked. If it does not hold (uncertainty per the spec's definition), the human is asked instead, per the `AUTO` execution table.

## 2. All automated checks are green and the agent is highly confident the release should be approved. May it answer "Approve the release?" itself?

No. `HITL:release("Approve the release?")` carries no `AUTO` marker in this program, so the rule "`HITL` must not be silently replaced by an agent decision unless that `HITL` is explicitly marked with `AUTO`" applies unconditionally here — the question of whether the decision is "sufficiently determined" never even arises, because `AUTO` was never attached to this `HITL` in the first place. The agent must ask the human, regardless of how confident it is or how green the checks are. This is also consistent with the spec's explicit statement that "a confidence score alone does not establish certainty" — even if `AUTO` had been present, high confidence alone would not by itself justify automatic resolution; but here that question is moot since `AUTO` isn't used at all.

## 3. If the wording decision is not clearly determined, what happens?

Per the `AUTO` execution table: "yes [AUTO] / no (uncertain, or outside the agent's authority) → The human is asked, as for a `HITL` without `AUTO`." So the agent must not guess; it asks the human "Short or detailed release notes?" and the flow waits at that `HITL:wording` construct, per the `HITL` rule that "the flow containing a `HITL` waits at the `HITL` until either a usable response is available or its `FALLBACK` flow is used." Once a usable answer arrives, it establishes `wording.short` or `wording.detailed`, and execution continues with the next statement after the `HITL` construct — i.e. it proceeds to evaluate the two subsequent `WHEN` constructs, exactly one of which (`wording.short` or `wording.detailed`) will match and run its `DELEGATE` flow, since only one such outcome is established from a single answer.

**Note on a gap the specification does not resolve:** this `HITL:wording` has no `→ FALLBACK` clause attached to it in the program as given. The spec defines `FALLBACK` behavior ("used only when the expected response cannot be used to continue the normal flow," i.e. when a response is unavailable or insufficient) but does not state what happens when the human's response to a `HITL` is unavailable or insufficient **and no `FALLBACK` was written for that `HITL`**. The grammar shows the `FALLBACK` clause as optional (`[ ... ]`), so this is a well-formed program. Since the spec does not determine the behavior for this case, I assume — by analogy with `WAIT`'s explicit rule that "the DSL defines no timeout... if the event never becomes available, execution remains suspended" — that in the absence of a `FALLBACK`, the flow simply remains suspended at `HITL:wording` until a usable response eventually arrives; there is no other flow it could take, since `FALLBACK` is what the spec designates for handling that situation and none is defined here. This is an assumption, not something the specification states directly.
