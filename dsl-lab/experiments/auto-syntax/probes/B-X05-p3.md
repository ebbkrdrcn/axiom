# Validity Analysis of go_harness DSL Snippets

## Snippet 1

```text
HITL:deploy("Deploy to production?") AUTO
WHEN deploy.yes
  → EMIT deployment
```

**VALID**

- The `HITL` statement matches the required form exactly: `HITL[:<name>]("<message>") [AUTO]` (Syntax → Statement table), and the EBNF production `hitl = "HITL", [":" , identifier], "(", string, ")", ["AUTO"], NL, [...]`. `AUTO` is written directly after the closing parenthesis, on the same line, as required ("`AUTO` is written directly after the closing parenthesis of `HITL(...)`, on the same line" — AUTO section).
- `deploy` is a valid identifier used as the HITL's `<name>`.
- `WHEN deploy.yes` uses the condition form `<identifier>.<identifier>` (Conditional Flow: "`<condition>` has the form `<identifier>.<identifier>`"). This matches the rule that "The response establishes the outcome `<name>.<answer>`, where `<answer>` is one of the answers tested by the `WHEN <name>.<answer>` constructs that follow" (HITL section) — here `<name>` = `deploy`, `<answer>` = `yes`, and this is the (only) `WHEN` construct following the `HITL`, so it is a legitimate answer being tested.
- Indentation is well-formed: `HITL` and `WHEN` sit at the same (top) depth, and `→ EMIT deployment` is indented one level under `WHEN`, matching `when = "WHEN", condition, NL, INDENT, flow, DEDENT` and `item = "→", statement, [...]`.
- No `FALLBACK` is present, but the grammar marks the fallback block as optional (`[ INDENT , "→" , "FALLBACK" , ... DEDENT , DEDENT ]`), so its absence does not make the snippet ill-formed.

## Snippet 2

```text
DELEGATE implementation AUTO
VERIFY implementation
```

**INVALID**

- The AUTO section gives this exact pattern as its stated invalid example: "Invalid, because `AUTO` applies only to `HITL`: `DELEGATE implementation AUTO`".
- This is confirmed by the grammar: the `simple` production for `DELEGATE` is `("REQUIRE" | "DELEGATE" | "VERIFY" | "TRANSITION" | "EMIT"), argument, NL` — there is no slot for `AUTO` after the argument. Only the `hitl` production includes an optional `"AUTO"` token.
- Also stated directly: "`AUTO` is not a statement of its own and applies to no other statement. `AUTO` applies only to `HITL`" (AUTO section).

## Snippet 3

```text
AUTO HITL:deploy("Deploy to production?")
WHEN deploy.yes
  → EMIT deployment
```

**INVALID**

- Per the Syntax section, the only valid form for these keywords together is `HITL[:<name>]("<message>") [AUTO]` — i.e., the statement begins with `HITL`, and `AUTO` (if present) follows the closing parenthesis on the same line: "`AUTO` is written directly after the closing parenthesis of `HITL(...)`, on the same line" (AUTO section).
- The EBNF confirms the required token order: `hitl = "HITL" , [ ":" , identifier ] , "(" , string , ")" , [ "AUTO" ] , NL , ...`. `AUTO` must come after `")"`, not before the `HITL` keyword.
- Placing `AUTO` before `HITL` does not match this production (nor any other statement production in `simple`, since `AUTO` is not one of the listed simple-statement keywords and `HITL` is a distinct statement alternative). The line therefore does not parse as any valid statement, making the program not well-formed ("A program that violates a rule stated as 'invalid', 'may only', or 'must not contain' ... is not well-formed" — Programs, fragments, and validity).

## Snippet 4

```text
AUTO
  WHEN decision.uncertain
    → HITL("Approve?")
```

**INVALID**

- This is verbatim the spec's own "invalid" example: "Also invalid, because `AUTO` never contains a flow and uncertainty is not a condition: `AUTO` / `WHEN decision.uncertain` / `→ HITL("Approve?")`" (AUTO section).
- Explicitly stated rules violated: "`AUTO` is not a control-flow container. It does not contain `WHEN`, `→`, or an arbitrary flow." and "Uncertainty is not a DSL condition, state, variable, or keyword." (AUTO section).
- Grammar confirmation: `AUTO` appears in the grammar only as an optional trailing token inside the `hitl` production (`[ "AUTO" ]`); it is not one of the constructs listed in `statement = loop | when | fork | hitl | simple` that can open an `INDENT ... DEDENT` block, so `AUTO` followed by an indented `WHEN` block has no valid production.

## Notes / Assumptions

- No specification-underdetermined points required an assumption for Snippets 2–4; the specification directly labels equivalent constructs as invalid.
- For Snippet 1, the specification does not explicitly state what happens if a `WHEN` after an `AUTO`-marked `HITL` tests an `<answer>` that is not literally used elsewhere, but here `yes` is exactly the answer tested by the sole following `WHEN`, so per "the outcome `<name>.<answer>` ... is one of the answers tested by the `WHEN <name>.<answer>` constructs that follow," this is a well-formed, unambiguous case and required no additional assumption.
