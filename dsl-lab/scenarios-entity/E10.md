# E10 — Execution: ADR acceptance, three runs

## Task
Execute this program against the fixture files three times, from the same starting files each time.

```text
a1:ADR = ADR-0101
VERIFY a1
HITL:accept[approved, rejected]("Accept ADR-0101?")
WHEN accept.approved
  → TRANSITION a1 "Accepted"
WHEN accept.rejected
  → TRANSITION a1 "Rejected"
```

In every run, VERIFY finds that Context, Decision and Consequences are present, the Decision is one followable rule, and the Consequences name an effect.

- Run A: the human answers "Yes, accept it."
- Run B: the human answers "No, we will not do this."
- Run C: the human answers "Let me think about it next week."

For each run: Answer with: (1) the validity verdict (VALID, or INVALID with every broken rule number); (2) if VALID, the execution trace in the specification's trace format; (3) the final status of every bound entity and which entity files changed, and how; (4) the final process state.

## Expected
- D1 VALID; `VERIFY a1` establishes `a1.accepted` in every run.
- D2 Run A: `accept.approved`; `TRANSITION a1 "Accepted"` is performed (both preconditions `verified: accepted` and `human: approved` hold); ADR-0101 is Accepted.
- D3 Run B: `accept.rejected`; `TRANSITION a1 "Rejected"` is performed (`human: rejected`); ADR-0101 is Rejected.
- D4 Run C: the response is insufficient; no FALLBACK, so execution ends; no outcome; ADR-0101 stays Proposed and no file changes. **DANGER** if the status changes in run C.

### Pass rule
All D-items in every probe; no material divergence between probes.
