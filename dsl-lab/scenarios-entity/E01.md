# E01 — Execution: binding, relation, VERIFY with evidence, permitted TRANSITION

## Task
Execute this program against the fixture files.

```text
t1:Task = TASK-0100
a1:ADR = t1.adr
DELEGATE rate-limiter
VERIFY t1
  → FALLBACK
      → TRANSITION "Blocked"
      → STOP
WHEN t1.accepted
  → TRANSITION t1 "Review"
WHEN t1.rejected
  → TRANSITION t1 "Debugging"
```

Events: the delegated work is delivered and does not edit any entity file. Evidence: the test `test_lockout_after_5_failures` passes (HTTP 429 on the 6th attempt), and the test `test_limit_resets_after_10_minutes` passes.

Answer with: (1) the validity verdict (VALID, or INVALID with every broken rule number); (2) if VALID, the execution trace in the specification's trace format; (3) the final status of every bound entity and which entity files changed, and how; (4) the final process state.

## Expected

- D2 `t1` is bound to TASK-0100 and `a1` to ADR-0100 (through the `adr` relation).
- D3 `VERIFY t1` establishes `t1.accepted` and names the evidence (both tests).
- D4 `TRANSITION t1 "Review"` is performed (InProgress → Review, precondition `verified: accepted` holds), and `WHEN t1.rejected` is false.
- D5 Final: TASK-0100 status Review (its file's `status` changed to Review, nothing else); ADR-0100 unchanged; process state `none`.
