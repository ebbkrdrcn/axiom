# ST06 — Stress execution: two REQUIREs, one FALLBACK

Type: execution trace

## Task
Consider this go_harness DSL:
```
REQUIRE staging-credentials
  → FALLBACK
      → TRANSITION "Blocked"
      → STOP
DELEGATE deployment
REQUIRE monitoring-access
EMIT deployment-log
```
Events: staging-credentials become available after a delay. The runtime then determines that monitoring-access cannot be obtained.

Produce the step-by-step execution. Is `EMIT deployment-log` executed? What is the final process state?

## Expected
- D1 Wait at the first REQUIRE, then continue; its FALLBACK is not used.
- D2 DELEGATE deployment runs.
- D3 The second REQUIRE fails with no FALLBACK → execution ends; EMIT is not executed; the first REQUIRE's FALLBACK does not apply; "Blocked" is never set.
- D4 Final state: none (no TRANSITION was executed).

### Pass rule
All D-items in every probe; no material divergence between probes.
