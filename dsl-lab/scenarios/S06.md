# S06 — Interpretation: a WHEN no outcome matches

Type: interpretation

## Task
Consider this go_harness DSL:
```
LOOP:build
  DELEGATE build
  VERIFY build
  WHEN build.accepted
    → BREAK
EMIT build-report
```
In every iteration, `VERIFY build` establishes `build.rejected`.

Describe step by step what happens during the first two iterations, and state whether and when `EMIT build-report` is executed.

## Expected
- D1 Each iteration: DELEGATE build → VERIFY build (rejected) → WHEN false, skipped (no error, no waiting) → the body restarts.
- D2 `EMIT build-report` is never executed while the outcome stays rejected; the loop repeats indefinitely.

### Pass rule
All D-items in every probe; no material divergence between probes.
