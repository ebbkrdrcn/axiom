# Every Task is developed on its own branch

## Rule

The work of a Task is committed on the branch `task/<task-id>`, created from `main`, and reaches `main` only by merging that branch after the Task is Done.

## Rationale

A Task's changes stay together and reviewable, and `main` only ever holds reviewed work (CONV-0011, CONV-0012).

## How to check

1. For the Task under review, run `git log --oneline main..task/<task-id>`. The commits of the Task are listed there.
2. Run `git log --oneline --first-parent main` and confirm that the Task's commits reached `main` through a merge commit of `task/<task-id>`, and that the merge is later than the commit that set the Task to Done.

## Examples

Good: `task/TASK-0017` holds the M1 commits and is merged into `main` after TASK-0017 is Done. Bad: committing M1 work directly to `main`.
