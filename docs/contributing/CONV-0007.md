# Each validity rule is its own `Rule` class

## Rule

Each validity rule is its own `Rule` class, registered in the rule registry, and no existing rule is edited to add a new one.

## Rationale

Rules evolve with the DSL. Keeping one class per rule keeps every rule testable, lets diagnostics name the rule, and follows the open/closed principle.

## How to check

Each rule id (V1…) maps to exactly one class in `runtime/axiom/dsl/rules/`. A change that adds a rule adds a class and a registry entry.
