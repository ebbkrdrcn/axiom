# Checks collect diagnostics and return them instead of raising exceptions

## Rule

Checks collect diagnostics and return them instead of raising exceptions; exceptions are only for programming errors.

## Rationale

A protocol author, often a model, needs every problem reported in one pass, each with its rule id, position and a fix hint (the Notification pattern).

## How to check

Every check function returns a collection of `Diagnostic` objects. Look for `raise` in checking code: each one signals a bug and is never used for a user-facing problem.

## Examples

Good: `diagnostics.add(Diagnostic(rule="V2", …))`. Bad: `raise ValidityError("BREAK outside LOOP")`.
