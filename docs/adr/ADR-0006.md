# One failure rule: FALLBACK or end

## Context

v1 left open what happens after an unusable HITL, an unsatisfied REQUIRE, or a fallback that does not stop (F-10, F-11, F-29, F-34; DP-4, DP-6). The Entity Model added more failing operations.

## Decision

A failing operation (binding, `REQUIRE`, `HITL`, `VERIFY`, `TRANSITION <name>`) runs its `→ FALLBACK` if it has one; otherwise execution ends, as with `STOP`. A fallback flow MUST end with `STOP` or `BREAK` (V8). A failed operation changes nothing and establishes no outcome. Bindings take no FALLBACK.

## Consequences

- No execution path waits forever or continues in a degraded mode after a failure.
- The trace records failures as `failed: <reason>; fallback` or `failed: <reason>; stop`.

## Alternatives Considered

- Continuing after the fallback flow (DP-6 A): an ambiguous next step.
- Implicit escalation to a human (DP-4 D): hidden HITLs.
