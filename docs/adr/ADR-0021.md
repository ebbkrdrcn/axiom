# Axiom is a stateless rulebook and interpreter; work happens in the target project

## Context

Axiom has to be usable on any project. The earlier drafts did not separate three things:

- the system: rules, types, protocols and actors;
- a project's knowledge;
- the work itself.

The Test 3 DANGER errors showed that models can read the control flow of a protocol but do not always apply it correctly. Determinism therefore has to come from the system, not from the model.

## Decision

### Roles

- **Axiom is the rulebook.** It is the single source of truth for the DSL, the entity types, the protocols and the actor definitions.
- **Axiom is the interpreter.**
  - It steps through a protocol.
  - It evaluates the control flow: LOOP, WHEN, FORK, BREAK, outcomes.
  - It checks bindings, including counting the files that declare an identity.
  - It checks transitions and preconditions, including a stale `verified:`.
  - It returns the next step to the agent.
- **Axiom is stateless.** It exists to make execution deterministic.
- **The work happens in the target project.**
  - The agent runs in the project directory, delegates to sub-actors, and changes files there.
  - The agent keeps only the judgements that need a model:
    - the work itself;
    - VERIFY evaluation;
    - mapping an ASK response to an answer;
    - the epistemic AUTO decision.
- **A project's `docs/` is its epistemic knowledge.**
  - The entity instances (ADRs, Tasks, …) live there.
  - Earlier ASK answers accumulate there.
- **Execution state lives in the project,** in `.axiom/`:
  - `.axiom/run.json` is the interpreter state. It is not committed.
  - `.axiom/ledger.jsonl` is the audit record. It is committed.

  Axiom reads and returns this state on each call.

### Connection

- `axiom project start <path>` leaves a small `AGENT.md` in the target project. It tells the agent to use axiom for rules and execution, and that the target is this project.
- The agent reaches axiom through its MCP server. Content is requested **by name**, never by path. Examples: `protocol: task-delivery`, `actor: python-dev`, `type: Task`.
- Many sessions on many projects can use the same axiom at the same time. There is no shared mutable state in axiom.
- **Paths.** Every file path that axiom states or returns is relative to the target project's root, for example `docs/tasks/TASK-0100.md`.

### Axiom's own structure

```
spec/        dsl.md, entity-model.md
rules/       types/<type>/, protocols/<name>.dsl, actors/<name>.md
runtime/     the interpreter as a Python package: parser, interpreter, entities, mcp, cli
templates/   AGENT.md template, docs/ skeleton
tests/       interpreter tests; the lab's expected traces serve as golden tests
lab/         the test corpus, tools, findings and reports
docs/        axiom's own epistemic knowledge: its ADRs and Tasks
```

### Axiom develops itself

- Axiom is also a target project: its own `docs/` drives its development.
- Execution uses a **stable** version of axiom: a release or a pinned commit. Development changes the working copy.
- A change reaches execution only after its tests pass and a new version is made. This works like a self-hosting compiler.

### Language

The runtime is written in Python, like the existing tools. MCP has an official Python SDK.

## Consequences

- The DANGER class seen in Test 3 is handled by the interpreter rather than by the model.
- The DSL spec can later be split into two parts: what the interpreter implements, and the few judgement rules the model must follow.
- The corpus shifts its focus from "does the model follow control flow" to the four judgement points.
- **ADR-0020 is corrected.** Entity instances stay in the project's `docs/`, and only the types move into axiom.

## Alternatives Considered

- **Axiom as a stateful service shared by the sessions:** this is unnecessary. The state belongs with the project and its work.
- **Copying the rules into each project:** there would be many sources of truth, and they would drift apart.
- **The model interpreting the protocol from the spec (the current lab setup):** it tops out below full determinism.
