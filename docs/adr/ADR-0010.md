# Entity Model: entities by identity, contracts per type

## Context

Processes need to operate on project things such as tasks and ADRs with the same determinism as the DSL itself.

## Decision

Adopt `entity-model.md`: an entity has one immutable identity and one Entity Type. Each type has one Template (structure) and one Definition (statuses, transitions with preconditions, verification criteria). An entity's data lives in one authoritative representation; in this project that is a Markdown file with YAML front matter under `docs/`. Contracts live in `docs/types/<type>/`. The first types are Task and ADR.

## Consequences

- The project's own ADRs and tasks are managed as entities. This is the first real use of the DSL.
- Tests use frozen copies of `docs/`, because the live files change.
- Open questions in `entity-model.md` (entity creation, status conditions, concurrent changes) are future ADRs.

## Alternatives Considered

- File-path references: they break on renames and do not carry a type.
