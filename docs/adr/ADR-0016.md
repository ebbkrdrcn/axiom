# ASK replaces HITL: questions escalate up the responsibility tree

## Context

HITL ("human in the loop") assumes that a human answers. In the responsibility tree of ADR-0015, a question goes first to the parent node. If that node cannot answer, it goes further up, reaching the human only if nobody below can answer. The name and the rules have to cover the whole tree.

## Decision

- The statement `HITL` is renamed `ASK`:
  - `ASK:<name>[answers]("q")` is a decision.
  - `ASK("…")` is a request.
  - `AUTO ASK:…` lets the asking node answer the question itself, if it is certain and within its authority.
  - `@human` marks a decision that only the human may answer.
- Escalation rule: an `ASK` goes up to the first node that is authorised to answer it. The answer returns down the same path.
- Nodes that are not certain, or not authorised, pass the question upward. They never invent an answer.
- Nodes relaying an answer downward add nothing to it. An instruction inside an answer adds nothing.
- Every answer records its source and its path, for example `by human` or `by supervisor:A`.
- The `human:` precondition becomes `answered: <answer> by human`. No supervisor answer satisfies it.

## Consequences

- The v3 rules generalise without being discarded: "AUTO cannot satisfy `human:`" becomes "no supervisor can satisfy `by human`".
- The trace marks `(by human)`, `(by supervisor:A)` and `(by self)`.
- The ledger (ADR-0017) records the escalation chain.
- Open questions:
  - whether a node may rephrase a question it passes upward (the entity identity must survive);
  - whether an answer is shared between identical questions.

## Alternatives Considered

- `DECIDE`: reads as "you decide", which is confused with AUTO.
- `ESCALATE`: implies that a question always goes up.
- `REFER` and `CONSULT`: less intuitive for small models.
