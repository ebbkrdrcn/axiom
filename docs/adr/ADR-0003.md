# Decision HITL with a declared answer list

## Context

In DSL v1, `WHEN` could not refer to a human decision, and the probes invented outcome names (F-07, DP-3). Leaving the answer set implicit (DP-3 A) left open which answers exist.

## Decision

A decision is written `HITL:<name>[<a>, <b>, …]("<question>")`. The answer list is closed. The human's response establishes `<name>.<answer>` for exactly one listed answer, and `WHEN <name>.<answer>` tests it. `HITL("<request>")` asks for input or an action and establishes no outcome. A response is usable, insufficient or unavailable, as defined in `dsl.md`.

## Consequences

- V6 can check every `WHEN` against the declared answers, and V7 forbids duplicate names or answers.
- Open: mapping a paraphrased answer that carries extra feedback (F-36).

## Alternatives Considered

- Answers implied by the following `WHEN`s (DP-3 A): the answer set depends on distant lines.
- A fixed `approved`/`rejected` vocabulary (DP-3 B): too narrow for non-approval decisions.
