# Protocols take entities as inputs: `INPUT <name>:<Type>`

## Context

A protocol bound its entities to fixed identities, for example `t:Task = TASK-0100`, and repeated the identity by hand in its questions (`"Is TASK-0100 done?"`). Such a protocol serves one Task only. A supervisor must be able to run the same protocol for each piece of work it hands to an actor, so the entity has to come from the caller.

## Decision

A protocol declares each entity it takes with a line `INPUT <name>:<Type>` at the top of the program, before its bindings. The caller gives the identity when it starts the execution (for example `axiom run task-delivery t=TASK-0100`). An input is a binding in every other respect. In the question or request of a `HITL`, `{<name>}` stands for the identity of the bound entity.

## Consequences

- One protocol serves every entity of its type. `rules/protocols/task-delivery.dsl` takes its Task as an input.
- `spec/dsl.md` gains the statement, the text references and their validity rules (V11 for placement, V12 for references to unbound names), and its grammar gains `input` and `text`. `lab/tools/dslcheck.py` follows.
- The `human:` precondition can rely on `{<name>}` instead of a hand-written identity in the question.
- M1 (TASK-0017) parses and checks `INPUT` and references. The interpreter (M3) takes the identities from the caller, records them in `.axiom/run.json` and the ledger, and does not start an execution whose inputs are missing or not satisfied.
- The owner chose the keyword over a bare `t:Task`: an explicit keyword cannot be produced by accidentally omitting `= <identity>`, and a model reads it more reliably.

## Alternatives Considered

- `t:Task` without `=`: no new keyword, but a forgotten identity silently becomes an input.
- `t:Task = ?`: a placeholder that adds a symbol without adding meaning.
- `PROTOCOL task-delivery(t:Task)`: a function-like signature that repeats the name the file already carries.
- Entities created during execution, iteration over a collection and calling a protocol from a protocol: deferred to the interpreter and actor design (M3).
