# A maintenance mode closes the improvement loop

## Context

- **A scored, observable system will exist.** Once protocols run for real, each run is recorded:
  - the ledger (ADR-0017);
  - ASK chains (ADR-0016);
  - VERIFY outcomes;
  - the qualification results of the corpus (ADR-0019).

  Over time this shows what went wrong, and where. Problematic protocols, roles, actor definitions and model assignments become observable.

## Decision

### Maintenance mode: an improvement loop run by the system itself

Maintenance mode is a protocol that the system runs on its own operational data. It follows the same rules as any other protocol: ASK, epistemic knowledge and entity transitions.

1. **Observe.** Collect the signals from the ledger and from test results:
   - failed or blocked runs;
   - DANGER errors, and near misses such as a TRANSITION refused by the harness;
   - repeated ASKs about the same topic;
   - VERIFY rejection rates;
   - loops that needed many rounds;
   - ASKs that reached a human although the knowledge already existed.
2. **Diagnose.** Attribute each signal to a cause:
   - a protocol;
   - a role or actor definition;
   - a model assignment;
   - the tool layer;
   - missing knowledge.
3. **Propose.** Draft a change: a protocol edit, an actor definition edit, a model reassignment, or a new mechanical check. Every incident also becomes a new corpus scenario.
4. **Verify.** Run the change against the qualification corpus. The change must not regress, and it must make zero DANGER errors.
5. **Approve.** An `ASK` to the owning role.
   - The architect approves changes to protocols and actors.
   - Security approves authority and tool-layer changes.
   - Nothing changes in production without that approval.

### Where the proposals live

The proposals and their outcomes are entities too: a new type, for example an `Improvement`, with statuses such as Proposed, Verified, Approved, Applied and Rejected. The loop is therefore itself auditable.

## Consequences

- The system improves from its own use, and people approve each change.
- The ledger has to record enough to attribute a failure to a protocol step, an actor, a model and the tool-layer version.
- The corpus grows from real incidents, which strengthens the qualification exam.

## Alternatives Considered

- **Manual improvement only:** the observational data would exist, but nobody would act on it systematically.
