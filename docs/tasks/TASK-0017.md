# M1: DSL core (lexer, AST, parser, validity rules)

## Description

Roadmap milestone M1. Build `runtime/axiom/dsl/`:

- a token enum and keyword table;
- the `INPUT <name>:<Type>` statement and `{<name>}` references in texts (ADR-0022);
- a scanner and generator lexer that produces INDENT and DEDENT tokens and gives every token its position;
- frozen dataclass AST nodes that carry their positions;
- a recursive-descent parser that mirrors the EBNF and recovers in panic mode;
- Notification-style diagnostics, each with a rule id, position, message and hint;
- a visitor base class and a symbol table;
- one `Rule` class per V1–V12, registered in a registry;
- the facade `axiom.dsl.check()` and the CLI command `axiom check`.

Follow the Active conventions in `docs/contributing/`.

## Acceptance Criteria

- The differential test shows zero disagreement with `lab/tools/dslcheck.py`, both on the VALID/INVALID verdict and on the set of rule ids, for:
  - every example in `spec/dsl.md`;
  - every lab scenario program;
  - every probe-authored program in `lab/iterations/*/probes/`.
- `mypy --strict runtime/` is clean.
- The unit tests for the lexer, the parser and the rules pass.

Implementer's evidence (2026-09-26), branch `task/TASK-0017`:

- **Layout.** `runtime/axiom/dsl/`:
  - `tokens` (token kinds and an immutable keyword table);
  - `lexer` (generator; INDENT/DEDENT; every token has its line, column and a `spaced` flag);
  - `nodes` (frozen dataclass AST with `line` and `column`);
  - `parser` (recursive descent; one method per statement form, chosen by the first token);
  - `issues` (the syntax facts the lexer and parser record);
  - `diagnostics` (`Diagnostic` and the `Report` notification);
  - `visitor`, `symbols`;
  - `rules/` (one `Rule` class per V1…V12, in `RULE_CLASSES`, applied by a `RuleRegistry`).
- **Facade and CLI.** The facade is `axiom.dsl.check()`, and `runtime/axiom/cli.py` provides `axiom check FILE…` and `axiom check --md FILE…`. `pyproject.toml` installs the `axiom` command.
- **Recovery.** A line that matches no statement form becomes an `Invalid` node that keeps its children, following Indentation rule 2. The rules skip it, and its issue is reported under V1, V4 or V5.
- **Nesting.** The parser accepts any nesting. Which children a statement may have is judged by the rules (V1, V4, V8, V9), so each violation carries the rule id the spec gives it. This is where the parser departs from a literal transcription of the EBNF.
- **Differential test.** `tests/dsl/test_differential.py` finds zero disagreement with `lab/tools/dslcheck.py`, on both the verdict and the set of rule ids. The corpus is 630 programs: every fenced program block in `spec/dsl.md`, `lab/scenarios*/` and `lab/iterations/*/probes/`, and `rules/protocols/*.dsl`. Disabling V8, and separately the JOIN part of V9, made the differential and rule tests fail.
- **Fixes to the reference checker.** Three places where `dslcheck.py` disagreed with the spec were fixed to follow it. None of them changed a verdict in the corpus; rule-id sets changed for 10 of 629 blocks.
  1. A `→` item under a `HITL`, `REQUIRE`, `VERIFY` or `TRANSITION <name>` is V4, and a plain line there is V1. Before, both were reported as "V1/V4".
  2. A `→ BREAK` that is itself a FORK branch is V3. Before, only its ancestors were examined.
  3. An unreadable line stays in the tree as an opaque parent, so its indented lines remain its children (Indentation rule 2). Before, they were attached to an earlier line and produced cascade errors, for example a spurious V1 in the S05 programs.
- **Checks.**
  - `mypy --strict runtime/`: no issues in 28 files.
  - `python3 -m pytest`: 73 passed. The lexer, parser and rule tests are in `tests/dsl/`, and each rule has a program that breaks only that rule.
  - CONV-0001 is automated by `tests/test_stdlib_only.py`.
  - The CONV-0004 command reports no package without tests.

Non-blocking findings and what was done:

1. **`LOOP:x = TASK-0001` was read as a malformed `LOOP` instead of a binding named `LOOP`.** Fixed: a line of the form `<word>:<word> = …` is parsed as a binding even when the name is a keyword. A parser test covers it.
2. **The corpus is not all genuine programs.** It is 221 `text` blocks, 15 `invalid` blocks, 393 untagged blocks and 1 protocol. Some untagged blocks are traces or prose fragments; both checkers reject those in the same way. So the "630 programs" above means 630 checked blocks, of which about 237 are tagged programs.
3. **The count of changed rule-id sets depends on how the old "V1/V4" label is counted.** Eight changes are the S05 cascades (fix 3). Two more appear when "V1/V4" is read as both ids (fix 1). No verdict changed.

Not changed: a bare `FALLBACK` (without its arrow) stays V4, as before. The reviewer found V4 and V1 both defensible readings.
