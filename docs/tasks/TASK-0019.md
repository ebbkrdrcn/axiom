# M2a: Entity types, loading, structural validity, relations, bindings and indexes

## Description

The first half of roadmap milestone M2. Build `runtime/axiom/entities/`:

- **Type contracts.** Parse each type's `template.md`, `definition.md` and `representation.md` into an immutable `EntityType`: fields, sections, relations, statuses, transitions and collection directory.
- **Repository port.** An `EntityStore` port reads a project's files by paths relative to the project root, with a file-system adapter and an in-memory adapter for tests.
- **Structural validity.** Entities are loaded and checked against their Template. The checks return diagnostics and never raise (CONV-0005).
- **Identity and relations.**
  - Identity comes from the `id` field only. A duplicate id is reported.
  - Relation targets must exist and have the declared type.
- **Binding resolution.** An identity resolves only if exactly one file declares it, the entity is of the expected type, and it is structurally valid. A relation binding resolves only if the relation has exactly one target (`dsl.md`, Entities › Binding).
- **Index generator.** Produces the same `_index.md` output as `lab/tools/indexgen.py`.
- **CLI.**
  - `axiom entities check [DOCS]` replaces `entitycheck.py --all`.
  - `axiom index [--check] [DOCS]` replaces `indexgen.py`.

Follow the Active conventions in `docs/contributing/`.

## Acceptance Criteria

- `axiom entities check docs` gives the same verdict as `python3 lab/tools/entitycheck.py --all docs` for every entity file of `docs/`. It also agrees on every case of a differential test that mutates a copy: missing field, bad id format, undeclared status, missing section, duplicate id, missing relation target, wrong target type, and stale index.
- `axiom index` writes `_index.md` files byte-identical to those of `lab/tools/indexgen.py` for `docs/`.
- Binding resolution is tested for these cases: exactly one match, no match, two files with the same id, wrong type, structurally invalid, and a relation with zero, one or two targets.
- `mypy --strict runtime/` is clean and `python3 -m pytest` passes.

## Notes
Implementer's evidence (2026-09-26), branch `task/TASK-0019`:

- **Layout.** `runtime/axiom/entities/`:
  - `store`: the `EntityStore` port, with the `FileSystemStore` adapter (which refuses paths that leave the root) and `MemoryStore`;
  - `contracts`: `EntityType` and `TypeCatalog`; `formats` holds the field-format strategies (id, literal, choice, date, unchecked);
  - `markdown`, `model` (`Entity`, with `content_hash`), `validity`, `corpus`, `binding`, `index`, `diagnostics`;
  - the facade `Project`.
- **CLI.** `axiom entities check [DOCS]` and `axiom index [--check] [DOCS]`, with `--project` and `--rules`.
- **AC1, parity with `entitycheck.py --all`.** `tests/entities/test_entitycheck_parity.py` covers `docs/` and both lab fixtures. For each it applies 9 mutations: unchanged, missing field, bad id format, undeclared status, missing section, duplicate id, missing relation target, wrong target type, and stale index. It compares:
  - the per-file verdicts;
  - whether duplicates or relation problems are reported;
  - the set of stale indexes;
  - the exit status.

  All 27 cases agree. Disabling the status check made 3 cases fail.
- **AC2, indexes.** The same test runs `indexgen.py` and `axiom index` on copies in three conditions: as is, with every index removed, and with a new entity. The `_index.md` files are byte-identical in all 9 cases. Changing the table separator made 18 cases fail.
- **AC3, bindings.** `tests/entities/test_binding.py` covers:
  - exactly one match, even when the file name differs from the id;
  - no match, and a file named after the id but declaring another;
  - two files with the same id;
  - wrong type;
  - a structurally invalid entity;
  - a relation with zero, one or two targets, and an unknown relation.
- **Stricter than the reference, following "every value conforms to the Template".**
  - `type` must equal the type name.
  - Dates must be `YYYY-MM-DD`.
  - Choice fields must hold one of their values, for example `check`.
  - A section marked "at least one item" must contain a list item.
  - A `0..1` relation may not hold several targets.

  None of these changes a verdict on `docs/` or the fixtures.
- **Checks.**
  - `mypy --strict runtime/`: no issues in 39 files.
  - `python3 -m pytest`: 136 passed.
  - The CONV-0004 command passes.
- **References updated.** `CONTRIBUTING.md`, the How-to-check of CONV-0009 (an Active convention; only How to check changed), `lab/NEXT.md` and the READMEs now use the `axiom` commands. The lab tools remain as the reference for the parity tests.
