# M0: Convention and Milestone types, indexes, CONTRIBUTING and ROADMAP

## Description

Roadmap milestone M0.

- Define the `Convention` entity type in `rules/types/convention/`. Its instances are `docs/contributing/CONV-NNNN.md`.
- Define the `Milestone` entity type in `rules/types/milestone/`. Its instances are `docs/roadmap/MS-NNNN.md`. Add an optional `milestone` relation to Task.
- Turn the milestones of ROADMAP.md into Milestone entities, and reduce the root `ROADMAP.md` to a pointer to `docs/roadmap/_index.md`.
- Write the first conventions.
- Add an `_index.md` to every `docs/` directory, produced by a temporary generator script.
- Extend `entitycheck` so that it verifies each index against its files.
- Add a root `CONTRIBUTING.md` that points to `docs/contributing/_index.md`.
- State in the Entity Model and in each `representation.md` that `_index.md` is not an entity.

## Acceptance Criteria

- `rules/types/convention/` and `rules/types/milestone/` each contain `template.md`, `definition.md` and `representation.md`, consistent with the Entity Model. The Task Template has an optional `milestone` relation.
- M0…M6 exist as `MS-NNNN` entities, and `docs/roadmap/_index.md` shows their status and the progress of their Tasks. The root `ROADMAP.md` points to that index.
- The conventions listed under M0 in ROADMAP.md exist as `CONV-NNNN` entities with status Active, and each one names its check.
- `docs/_index.md`, `docs/adr/_index.md`, `docs/tasks/_index.md`, `docs/contributing/_index.md` and `docs/roadmap/_index.md` exist, and `entitycheck` reports them consistent with their files.
- `entitycheck` reports every entity VALID and ignores `_index.md` as an entity.
- The root `CONTRIBUTING.md` points to `docs/contributing/_index.md`.

## Notes

Implementer's evidence (2026-09-26):

- **New types.** `rules/types/convention/` and `rules/types/milestone/` each contain `template.md`, `definition.md` and `representation.md`. The Task Template has an optional `milestone` relation.
- **Milestones.** MS-0001…MS-0007 cover M0…M6. MS-0001 is Active; the others are Planned and each `requires` the previous one. `docs/roadmap/_index.md` shows each milestone's status and "Tasks done".
- **Conventions.** CONV-0001…CONV-0011 are Proposed, each with `scope` and `check`. They become Active after the independent review, because the owner approved the list for M0.
- **Indexes.** `docs/_index.md` and the indexes of `adr/`, `tasks/`, `contributing/` and `roadmap/` are generated by `lab/tools/indexgen.py`.
- **`entitycheck --all docs` passes.** This mode also checks relation targets and index consistency. A negative test on a copy detected each of the following:
  - a duplicate id;
  - a missing relation target;
  - a relation target of the wrong type;
  - stale indexes.
- **Pointers.** The root `CONTRIBUTING.md` points to `docs/contributing/_index.md`, and `ROADMAP.md` points to `docs/roadmap/_index.md`.
- **`_index.md` is not an entity.** The Entity Model (Layout) and every `representation.md` say so, and `entitycheck` ignores it.

Independent review 1 (2026-09-26): **rejected**. AC3 was not satisfied: the conventions were Proposed, not Active. It also found a defect in CONV-0004: "layer" was undefined, and the check was declared `mechanical` although part of it was manual. CONV-0004 has been rewritten, with layer = package under `runtime/axiom/` and check = `review`. It needs verification before the conventions can become Active.
