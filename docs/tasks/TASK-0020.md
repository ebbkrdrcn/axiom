# M2b: Preconditions and permitted changes

## Description

The second half of roadmap milestone M2, on top of TASK-0019.

- **Preconditions.** Parse the precondition column of each Definition's Transitions table into typed preconditions: `none`, `verified: accepted|rejected`, `human: <answer>` and `field <f> is set`. Evaluate them against an execution context supplied by the caller (the interpreter, M3).
- **Stale `verified:`.** A `verified:` precondition is stale if the entity's content hash has changed since the VERIFY (F-62).
- **Transitions.** A transition is permitted only if its Definition declares it and every precondition holds.
- **Permitted changes.** State each Definition's permitted changes as a table that a program can read. Implement a check that compares two versions of an entity and reports every change the table does not permit.

## Acceptance Criteria

- Every precondition form of `dsl.md` (Entities › Preconditions) is parsed and evaluated, with tests for the holding and failing cases of each.
- A `verified:` precondition fails when the entity changed after its VERIFY, and holds when only a `TRANSITION` on that entity changed it.
- The permitted-changes check reports a change to a protected field or section and accepts a permitted one, for every type in `rules/types/`.
- `mypy --strict runtime/` is clean and `python3 -m pytest` passes.
